# TASK-092a: Operational map from real data – importer profile, tiled download, the Suwałki theatre map (5 km hexes, ~340 × 277 km)

- **Status**: ready
- **Layers**: tools (Python, offline) + data + docs (ADR amendment, credits)
- **Depends on**: TASK-087, TASK-108
- **Model**: opus (geodata over a ~94 000 km² area, tiled download, coastline, determinism, import size and time)
- **Topic**: Two-layer game

## Goal

The operation is played on a real **regional theatre** around the Suwałki Gap – north-east Poland, the Kaliningrad oblast, southern Lithuania and western Belarus (human decision 2026-11-01, GDD "Operational layer" → "Theatre", "Operational map"): a 5 km hex map imported from the same real data as the battle maps, big enough that attacking Kaliningrad or Belarus is a real option on the map. Reworked 2026-11-01 from the earlier 20 × 16 Suwałki Gap map.

## Acceptance criteria (testable)

Importer (`tools/import_map.py`, Python tests in `tools/test_import_map.py`):

- [ ] New option `--profile=tactical|operational` (default `tactical`; tactical output byte-identical to today – the existing golden test stays green unchanged).
- [ ] `operational` sets: hex default 5000 m, sample lattice **250 m** (`--sample=` overrides; tactical keeps 25 m), DEM **Copernicus GLO-90** (`--dem=glo30|glo90`, default `glo90` for `operational`, `glo30` for `tactical`; GLO-90 COG tiles `Copernicus_DSM_COG_30_N<lat>_00_E<lon>_00_DEM.tif` from the same open bucket, cached under `~/.cache/eastern-flank/maps/dem/`; the reader handles both tile widths – test on a synthetic GLO-90-sized fixture tile), and the classification in GDD "Operational map": water share ≥ 0.50 → water; urban ≥ 0.15 → urban; forest ≥ 0.50 → forest; marsh ≥ 0.25 → marsh; relief ≥ 60 m → hills; else plains (never fields). Thresholds are CLI options with these defaults (`--water-share`, `--urban-share`, `--forest-share`, `--marsh-share`, `--hills-relief`).
- [ ] Unit tests of the operational classifier with synthetic counts: 50 % water / 50 % forest → water; 49 % water, 51 % forest → forest; 15 % urban + 60 % forest → urban; 49 % forest, 26 % marsh → marsh; 49 % forest, 0 % marsh, relief 60 m → hills; same with relief 59.9 m → plains; 100 % farmland → plains.
- [ ] Roads in `operational`: only `highway` motorway / trunk / primary / secondary and their `_link`s (a `tertiary` way gives no link – test); rivers: only `waterway` river / canal (a named `stream` gives no link – test). The corner-clip length scales with the hex: `CLIP_M × hex / 250` (800 m at 5 km; test with a line clipping a corner by 700 m → no link, 900 m → link).
- [ ] **Tiled Overpass download**: the `operational` query asks only for what the profile reads (forest / wood, water, wetland, the urban `landuse` values, the four road classes, river / canal) **plus** `natural=coastline` ways and `boundary=administrative` + `admin_level=2` ways (country borders – read by TASK-113, downloaded now so TASK-113 runs offline). The map's bbox (+ 500 m) is split into tiles on a fixed **0.5° × 0.5°** grid aligned to multiples of 0.5° (`--tile-deg=` overrides; tiles reusable by other maps), each cached as its own file under `~/.cache/eastern-flank/maps/osm/`. A failed tile is retried (up to 3 times, with a pause) and the run continues where it stopped (finished tiles are never fetched again). `--offline` with a complete cache never downloads (test with a fake cache); a missing tile fails with a clear message naming the tile.
- [ ] **Tiling does not change the result**: tiles are processed one at a time (only one tile's JSON in memory); areas that appear in several tiles are rasterised again with the same "higher class wins" rule, which is idempotent. Test: the synthetic operational fixture imported with one tile and with 4 tiles (`--tile-deg` small enough) gives byte-identical output.
- [ ] **Sea from the coastline**: OSM has no sea polygons, so `natural=coastline` ways are rasterised as barriers on the sample lattice and a 4-connected fill from `--sea-seed=<lat,lon>` points (repeatable; the `operational` profile has built-in defaults for the theatre: one in the open Baltic, e.g. 55.30 N 20.60 E, one in the Curonian Lagoon, e.g. 55.10 N 21.05 E – the agent verifies both on a map) marks the reached points as water. Water polygons that already cover the sea (`natural=bay`, `water=lagoon`) are unaffected. Test: a synthetic fixture with a coastline and a seed → the points on the seed's side are water, the land side is not; a seed on land → error.
- [ ] Determinism: a synthetic fixture imported with `--profile=operational --hex=1000` (fixtures in `tools/import_map_fixtures/`, regenerated by `--make-fixtures`; including a coastline and a tile boundary) is byte-identical to a committed golden `tests/fixtures/maps/sample_op_map.tres` and to a second run.

Data (GDScript tests in `tests/unit/test_operational_map_data.gd`):

- [ ] `data/maps/suwalki_theatre.tres` – REAL data: `--profile=operational`, centre **54.20 N 22.90 E**, **68 × 64** hexes (columns × rows), `hex_spacing_m` 5000, CRS `EPSG:32634` (UTM 34N for the whole map, also east of 24 E); `ImportedMap.find(&"suwalki_theatre").problem() == ""` and `to_grid()` has 4 352 tiles. If a place below misses the edge rule, the agent may move the centre by ≤ 0.1° (record it); a different size goes back to the human.
- [ ] Places inside (test with their WGS84 coordinates projected by the map, listed in the test): Kaliningrad, Chernyakhovsk, Sovetsk, Olsztyn, Białystok, Ełk, Suwałki, Augustów, Grodno, Lida, Marijampolė, Kaunas, Vilnius – each on a tile ≥ 2 hexes from every map edge.
- [ ] The tactical sample lies inside it: the middle tile of `data/maps/suwalki.tres` maps through `suwalki_theatre.projected_to_tile` to a tile that is not water.
- [ ] Sanity of the real import (test): water hexes ≤ 15 % of 4 352; the hexes of the sea seeds and of Lake Śniardwy (≈ 53.75 N 21.73 E) are water; ≥ 5 of the 7 city hexes (Kaliningrad, Vilnius, Kaunas, Białystok, Grodno, Olsztyn, Suwałki) are urban (the tuning target is all 7); ≥ 300 hexes with a road link; ≥ 50 river hexes (the Neman / Nemunas, Biebrza, Narew, Pregolya …); ≥ 90 % of the land hexes form one region connected through land neighbours (adjacency only, no costs).
- [ ] Performance on the big map (test, headless, median of 3 in one process): `ImportedMap.find(&"suwalki_theatre").to_grid()` ≤ 1.0 s. The agent records in the implementation notes the `.tres` size, the time of `HexGrid.path_to` from tile (0, 0) to (67, 63) with an unlimited budget (the baseline TASK-092c's planner must beat – its budget is 30 ms), and the GDScript memory of the loaded grid.
- [ ] `data/maps/CREDITS` lists the map (inputs incl. GLO-90, download date, rebuild command); `test_maps_are_credited` passes.
- [ ] `suwalki_theatre` is not offered as a battle scenario (it is not in `Scenario.NAMES`; nothing else lists `data/maps/` – check the main menu / devtools scenario lists).

Measurements (implementation notes + ADR): number of tiles, total download size and time of the first run, cache size, offline import time (target ≤ 20 min on the dev machine; if it is far above, profile and say where the time goes before tuning anything), peak memory. If the public Overpass server refuses tiles (timeouts, 429), reduce `--tile-deg` and record it.
