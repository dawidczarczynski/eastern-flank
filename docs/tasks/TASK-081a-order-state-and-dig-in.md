# TASK-081a: Order state, action-slot rule and Dig in (core)

- **Status**: done
- **Layers**: core (+ data `.tres`); no presentation, no AI
- **Depends on**: TASK-089a (done)
- **Sections**: GDD "Unit orders", GDD "Combat"; ARCHITECTURE "Events" (via `tools/doc.py architecture`)
- **Model**: sonnet

## Goal

Orders exist as a rule: a unit can spend its action slot on **Dig in** (+2 defence until it moves), and the machinery (data, state, codec, events) is ready for the other orders.

## Acceptance criteria (testable)

- [ ] `OrderDefinition` resource (`src/core/data/`, `data/orders/dig_in.tres`): id, allowed unit classes (`infantry`, `tank`), `defence_bonus` 2; `OrderRules.orders_for(unit)` lists the orders its class has (MLRS: none yet).
- [ ] `Unit` gets `dug`, `ambush`, `scoot_used` (bool) and `slot_order` (StringName); `GameState.snapshot()` adds `"dug"`, `"ambush"`, `"scoot_used"`, `"slot_order"` per unit **only when set** – the existing replay fixture still passes unchanged.
- [ ] `DigInCommand` (`order_dig_in {unit_id}`): sets `dug`, `has_attacked = true`, `slot_order = &"dig_in"`, `moves_left = 0`, activates the unit; events `unit_order_issued {unit_id, order: &"dig_in", target: own coord}` then `command_points_changed` when it applies.
- [ ] Damage: `compute_damage` adds 2 to a dug defender's defence – attack 5 vs defence 2, tile 0 → 3; dug → 1; dug on forest (+tile bonus) stacks: attack 7 vs 2 + 1 (forest) + 2 → 2. The forecast (`CombatForecast`) shows the same numbers.
- [ ] A dug unit that is attacked and counters still counters (dug only touches defence).
- [ ] Rejections (`validate()`): `game_over`, `unit_not_found`, `not_your_unit`, `no_command_points`, `order_not_available` (MLRS), `already_acted` (unit attacked or ordered this turn), `already_dug`. After Dig in: `AttackCommand` → `already_attacked`; `MoveUnitCommand` → `unreachable`.
- [ ] Moving a dug unit (after next turn starts) clears `dug` and emits `unit_order_cleared {unit_id, order: &"dig_in", reason: &"moved"}` after `unit_moved`.
- [ ] Turn start clears `slot_order`, `scoot_used`, `ambush` of the new current player's units but **not** `dug` (a unit stays dug turn after turn); an `EndTurnCommand` test for it.
- [ ] `CommandCodec` round trip (including JSON) for `order_dig_in`; unknown or malformed order dicts return null; `MatchRecord` version stays 2.
- [ ] Replay determinism: a scripted match with one Dig in replays to an identical snapshot; `tools/simulate.sh 200` (`poland,russia`) gives the same results as before (the AI does not use orders yet).
- [ ] `OrderRules.availability(state, unit_id, order_id)` returns `{enabled: bool, reason: String}` for any of the seven order ids, using `validate()`'s code; `resupply` and `camouflage` → disabled, `order_not_available` (for TASK-082's model).
- [ ] ARCHITECTURE events table lists `unit_order_issued`, `unit_order_cleared`; docs/CODEMAP regenerated by `tools/check.sh`.
