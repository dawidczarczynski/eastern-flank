# TASK-113: Country per hex – importer fills countries from OSM borders, `ImportedMap.country_at`, re-import the theatre

- **Status**: ready
- **Layers**: tools (Python, offline) + core (`src/core/data/imported_map.gd`) + data + presentation (borders on the staff map)
- **Depends on**: TASK-092a, TASK-093a
- **Model**: sonnet
- **Topic**: Two-layer game

## Goal

Every land hex of the operational theatre knows which country it belongs to – Poland, Lithuania, Belarus or Russia (Kaliningrad oblast) – so the rules can tell where a formation may go and what crossing a border means (GDD "Operational layer" → "Theatre", "Countries and stances"; human decision 2026-11-01: country borders move from TASK-112 into the import).

## Acceptance criteria (testable)

Importer (`tools/import_map.py`, tests in `tools/test_import_map.py`; reads the border ways TASK-092a cached, **plus a small borders-only download** because that cache is incomplete – see the first criterion):

- [ ] **Complete the border cache first** (found in TASK-092a, ADR 0018 "Known limitation"): the `admin_level=2` *ways* cached by TASK-092a miss most of the Poland–Russia and Lithuania–Russia (Neman) borders, which are untagged member ways of the country relations. Add a borders-only query under a new query version (e.g. the member ways of the `boundary=administrative` + `admin_level=2` relations inside the tile, clipped to the tile; the agent picks the form that does not download whole-country geometry), cached per 0.5° tile next to the existing tile files; the land-cover tiles are **not** re-downloaded. `--offline` with a complete cache never downloads; a missing border tile fails naming the tile. Tests: a fake cache lacking the border file → clear error; with it → the border ways of both files are merged without duplicates. Record the download size and time in the implementation notes and check by eye on the real data that the Poland–Russia border runs along the oblast's south edge and the Lithuania–Russia border along the Neman.
- [ ] New option `--countries=<ISO>:<lat,lon>[,…]` – the countries to assign, each with a **seed point** inside it (repeatable or comma list); the `operational` profile has built-in defaults for the theatre: `PL` Suwałki 54.10 N 22.93 E, `LT` Kaunas 54.90 N 23.90 E, `BY` Grodno 53.68 N 23.83 E, `RU` Kaliningrad 54.71 N 20.51 E (the agent verifies each on a map). `tactical` writes no countries (tactical output byte-identical to today).
- [ ] Method: the border ways are rasterised as **barrier points** on the sample lattice (supercover: every lattice cell a segment passes through, so no 4-connected leak through a diagonal), then a **4-connected flood fill** from each seed gives every reached non-barrier point that country; barrier points take the country of the majority of their 4 neighbours (ties: the first country in `--countries` order); water points are filled like land (lakes on a border are split by the border line).
- [ ] **Hex country** = the country with the most **land** (non-water) sample points of the hex (ties: first in `--countries` order); a hex with no land points (sea, a large lake) gets none. A seed on a barrier or outside the map → error; two seeds in one region → error naming both countries; a land hex left without a country while it has land points → error listing the first 5 hexes (a leak or a missing seed).
- [ ] Synthetic tests (small fixtures in `tools/import_map_fixtures/`, regenerated by `--make-fixtures`): a straight border between two seeds → each side one country, the border hexes go to their majority; a diagonal border → no leak (the countries stay separated); a border with a lake across it → the lake hex has none, the shores keep their countries; a gap in the border line → error "two seeds in one region".
- [ ] Output: `ImportedMap` gets `countries: PackedStringArray` (ISO codes in `--countries` order, e.g. `["PL", "LT", "BY", "RU"]`) and `country_rows: PackedStringArray` (one character per tile: `0` … `9` = index into `countries`, `.` = none); written after the link rows. The operational golden `tests/fixtures/maps/sample_op_map.tres` is regenerated (with two countries), deterministic and byte-identical on a second run.

Core (`src/core/data/imported_map.gd`, GDScript tests):

- [ ] `problem()` also checks: `country_rows` empty (old maps, tactical maps – valid) or one row per map row with the map's width; only digits < `countries.size()` and `.`; no country on a water tile; `countries` entries are two upper-case letters, no duplicates. One test per broken case.
- [ ] `country_at(coord: Vector2i) -> String` – the ISO code or `""` (water, off the map, no country rows). Tests on a hand-made `ImportedMap` (3 × 2: `"0.1"`, `"001"` with `["PL", "LT"]`).
- [ ] `suwalki.tres` and the other tactical maps load unchanged (no country rows).

Data:

- [ ] `data/maps/suwalki_theatre.tres` re-imported offline with countries (same command as TASK-092a + defaults); all other lines byte-identical to the TASK-092a file (test: terrain / cover / link / elevation rows unchanged against a copy of the old rows, or the agent compares with `cmp` minus the new rows and records it).
- [ ] Real-map tests (`tests/unit/test_operational_map_data.gd`): every land hex has a country; each of the four countries owns ≥ 30 hexes; the places of TASK-092a fall into the right country – Kaliningrad, Chernyakhovsk, Sovetsk `RU`; Olsztyn, Białystok, Ełk, Suwałki, Augustów `PL`; Grodno, Lida `BY`; Marijampolė, Kaunas, Vilnius `LT`; the `RU` hexes form one region (the exclave: every `RU` land hex is reachable from Kaliningrad's hex through `RU` hexes only) and no `RU` hex neighbours a `BY` hex.
- [ ] The Suwałki Gap check: the shortest chain of land hexes from the `RU` region to the `BY` region through `PL` / `LT` hexes is 10–18 hexes long (the real gap is ≈ 65 km ≈ 13 hexes; the test prints the value; the agent records it).
- [ ] `data/maps/CREDITS`: the rebuild command gains the country options; the ODbL note already covers the borders.

Docs:

- [ ] ADR 0018 amendment (the TASK-092a section gets a paragraph "Countries"): seed fill, supercover barriers, majority rule, why not Overpass relations (country relations are whole-country multipolygons – far too big to download for a regional map).

View (borders on the staff map, `src/presentation/operational/`):

- [ ] The staff map draws **country borders** as a dash-dot line along the hex edges between hexes of different countries (helper `CountryBorders.edges(grid)` in core, pure, tested on a small hand-made grid: two countries → one polyline; an exclave → a closed ring; deterministic), one faint large **country name** (PL / LT / BY / RU as full names via `tr()`) centred on each country, and the hex card (TASK-093a) gains a **Country** line. Key **B** toggles borders and names (default on). Fine border lines are TASK-112; until then the line follows hex edges.
- [ ] 60 FPS stays (borders are baked with the map layers, measured and noted).

## Playtest (for the human)

1. Re-import / load the theatre (offline, as in the implementation notes), start → **Operation**.
2. A dash-dot line separates Poland from the Kaliningrad oblast along its south edge, Poland from Lithuania along the Gap, Belarus in the south-east; the names Polska / Litwa / Białoruś / Rosja sit faintly over the countries.
3. Hover hexes on each side of the Gap: the hex card names the country. Press **B**: borders and names disappear, again: back.
4. Check the Kaliningrad oblast is one closed region and the Gap (Polish–Lithuanian–Belarusian meeting point) looks right against a real map.
