Bottom bar windows – one window frame

1 · THE NEED

Every window opened from the bottom bar (and the turn bar) looks a bit different today. This proposal fixes one window component and shows the new Map options window in it. No new tokens, no new shapes – it is the frame the accepted Strike result report already uses.

Rule proposed for all windows (class StaffMapWindow, wraps FramedPanel + StaffMapCloseButton):

  • Docked panel (everything that is not a full overlay): left edge, x 16 / y 110, width tier 330 (default) or 420 (reports), height by content; one at a time (existing LeftWindow enum gets OPTIONS).
  • Frame: fill PANEL_STRONG, 1 px LINE, chamfers 0,16,0,16; tab (Chakra Petch 700 11, tracking 1) on ui.amber (side colour only for side-owned content); X 32 px top-right; Esc closes; opening one closes the others.
  • Full overlay (Decisions, Ladder) keeps scrim + plate but gets the same tab, X and edge so it reads as the same family.
  • Content rows: one toggle row (36 px, state box + label + key cap) and one info row (label left, mono value right) – used by options, strike panel and country card.
  • A window opened from a bar button lights that button (set_active) and the button closes it again.

2 · VARIANT A – docked left panel (recommended)

Options open in the same slot as the report / strike panel. Identical to every other bar window; nothing floats above buttons, so it never collides with toasts. States shown: all layers on / mixed.

5 · DECISIONS

  • Variant A accepted. Two kinds of windows: full-screen (Decisions, Ladder – unchanged) and docked (everything else, one shared StaffMapWindow).
  • A click on the map closes every docked window (left dock and right dock).
  • Formation panel = the same frame docked on the right edge (mirror of the left dock: x = screen width − 16 − 300, y 110, 300 px), tab in the side colour, X deselects; it is selection-driven, so a click on empty map deselects and closes it. It does not take part in the one-window-at-a-time rule of the left dock.
