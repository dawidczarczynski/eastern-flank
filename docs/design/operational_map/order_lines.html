Order lines v2: variant D – “Armed line”

The need. A / B / C differ in the gesture; the code already has B's gesture (select → hover route → click commits). What is missing is the feel and the information around the line. D keeps one state machine that accepts both click–move–click and press–drag–release, and adds five things A / B / C do not show: reach contour, posture alternative, destination ghost, converging attacks, editing an issued order – plus conflict and far-zoom rules.

Unchanged: commands and validation, border prompt, the ring on right click (INFO, cancel, explicit posture), MARCH dashed / DEFEND arc as accepted in TASK-092d. Taken from v1: flowing preview, glow, ATTACK double rail + spear + brackets. Dropped from v1: pull handle, order chip, posture rail under the counter, waypoints and road nodes (rules store only a destination).
