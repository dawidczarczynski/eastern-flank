# Architecture

## Layers

```
┌──────────────────────────────────────────────┐
│ Presentation  (Node, scenes, input, UI)      │  src/presentation/, scenes/
│  BattleController · MapView · UnitView · …   │
└───────────▲───────────────────────┬──────────┘
            │ events (Dictionary)    │ commands (Command)
┌───────────┴───────────────────────▼──────────┐
│ GameSimulation  – validate → apply → emit    │  src/core/game_simulation.gd
├──────────────────────────────────────────────┤
│ GameState · HexGrid · Unit · Terrain         │  src/core/
│ Commands                                     │  src/core/commands/
│ Scenario · BattleSetup · BattleResult        │  src/core/scenario.gd, battle_*.gd
│ AiPlayer (issues commands like a player)     │  src/ai/
├──────────────────────────────────────────────┤
│ Data: UnitDefinition, FactionDefinition, …   │  src/core/data/, data/
└──────────────────────────────────────────────┘
```

Dependencies point downward only. `src/core` doesn't know graphics exist.

## Flow of a single action

1. The player clicks a tile → `BattleController` creates `MoveUnitCommand(unit_id, coord)` (or `AttackCommand(attacker_id, target_id)` when the tile holds an enemy).
2. `GameSimulation.execute()` calls `validate()`. A rejected command → `command_rejected` signal with a reason code (e.g. `unreachable`, `out_of_range`, `already_attacked`; `AttackCommand` since TASK-131a also `too_close` – inside the minimum range – and `no_line_of_sight` – direct fire blocked by forest, buildings or hills, `LineOfSight` in `src/core/line_of_sight.gd`; the range and sight check is `AttackCommand.fire_problem`, also used for the counterattack, `CombatForecast.problem` and the AI). No new event types. Once `GameState.is_over()` (`end_reason != &""`) every command is rejected with `game_over`.
   `apply()` checks the victory rules through `BattleRules` (`src/core/battle_rules.gd`, ADR 0016): `MoveUnitCommand` → `capture` (objective ownership), `AttackCommand` → `after_strike` after each strike incl. the counter (ELIMINATE, DESTROY_SHARE; a strike that ends the battle gets no counter), `EndTurnCommand` → `at_turn_end` before the turn passes (TAKE_HEXES for the player ending the turn, then the turn limit with HOLD_HEXES). A battle end sets `winner` (−1 = draw) and `end_reason` and emits `game_over`.
3. `apply()` changes `GameState` and returns events; the simulation emits them via `event_emitted`.
4. `BattleController` turns events into animations (`UnitView.move_to`) and refreshes the HUD.

The AI (`AiPlayer.take_turn`) does exactly the same, just without clicks.

## Unit visuals

`UnitView` = model (`UnitModels.build`: a registry that loads `src/presentation/models/<unit_id>.gd`, built with `ModelParts` primitives and shared meshes/materials, faces +X; each unit model is built once per unit and faction, units get copies with their own node trees and the camo materials and the per-unit `wear_seed` restored per copy; `UnitModels.build` takes the unit id for the seed) + faction marker draped on the terrain (`OverlayGeometry`) + HUD `UnitLabel`, the **unit marker** (TASK-111: a fixed-pixel `Control` – faction tab, `UnitClassIcon` 15 × 11 px with the APP-6-like `HudShapes.class_glyph` of `UnitDefinition.unit_class`, short name, HP bar – whose bottom centre sits `UnitLabel.ANCHOR_OFFSET` 18 px above `Camera3D.unproject_position` of the unit's ground point, `UnitView.ground_point`, so the model scale never moves it; the models' `LABEL_HEIGHT` is no longer used for it). `BattleController._layout_markers` runs `UnitLabel.overlap_shifts` every frame (a marker overlapping one closer to the camera, `UnitView.distance_to_camera`, moves up by its own height, once), and a click on a marker (`UnitView.marker_hit`, the closest wins) counts as a click on that unit's tile; hover stays hex-based. The "done" dimming uses the pure helper `UnitStatus.is_done`; `BattleController` pushes selected/hovered/done state into the views.

Camera range (TASK-111): `CameraRig` zooms geometrically (`CameraMath.ZOOM_STEP_FACTOR` 1.25 per wheel notch) between `CameraMath.MIN_DISTANCE` 0.18 (≈ 26 m) and `MAX_DISTANCE` 46. Closer than `CLOSE_RANGE_DISTANCE` 7 the pitch stays at `PITCH_CLOSE` (~17°, towards the horizon), the look-at point follows the ground under the target (`CameraMath.look_height`, blended back to the fixed 0.4 by 14) and the ground clearance shrinks with (d / 7)² but never below `MIN_HEIGHT_METRES` 2 m (`CameraMath.clearance`, via `MapScale`), measured against `MapView.camera_ground_height` (the lattice, the finer `TerrainNear` surface and the water plane). The near clip plane follows the zoom (`CameraMath.near_plane`: 0.05 × d within 0.005..0.1), pan speed is proportional to the distance and the impact shake shrinks with it in the close range. `CameraMath.GROUP_DRAW_DISTANCE` 3.0 (`CameraMath.draws_group`, against `UnitView.distance_to_camera`) is the hook for the company group drawing (TASK-136). The hex grid fade (`OverlayGeometry.grid_alpha`) is anchored at `CLOSE_RANGE_DISTANCE`, so it did not change.

Mechanisms (TASK-043, ADR 0014): what a unit animates is declared per unit in its catalog entry (`mechanisms`, registry `docs/design/units/mechanisms.json`). The model file copies it into a `MECHANISMS` constant and stores it on the built model with `ModelParts.declare_mechanisms` (node metadata `mechanisms`, which survives `ModelParts.cached` copies); `UnitModels.mechanisms / mechanism(model, id) / has_mechanism` read it, so no `src/presentation` code touches `docs/`. Pivots activate a mechanism, the metadata parameterises it. `tests/unit/test_unit_mechanisms.gd` (helper `tests/mechanism_contract.gd`, test-only read of the catalog and registry) fails when a model's metadata differs from its catalog entry, when an implemented mechanism's pivots are missing, or when a model owns the pivot of a mechanism it doesn't declare.

Main menu and unit catalog (TASK-084): the game starts in `scenes/ui/main_menu.tscn` (`run/main_scene`; `MainMenu`: Start operation loads `scenes/battle/battle.tscn`, Language cycles `GameSettings.LOCALES` through `GameSettings.set_locale`, stored in `user://settings.cfg` and applied at start by `GameSettings.apply_saved`, Unit catalog loads `scenes/ui/unit_catalog.tscn`; widgets in code via `MenuStyle`). The catalog (`src/presentation/catalog/`, UI in `src/presentation/ui/unit_catalog.gd`) holds no `GameState`: `CatalogUnits` lists `data/units/*.tres` (path table, test-checked against the folder) grouped by class, `CatalogStage` shows one stand-alone `UnitView` (built by `UnitModels.build`, the battle's path) on a ground disc under the battle's sun and environment, `CatalogAnimations.for_model` maps the model's declared mechanisms to animation buttons (a table `mechanism id -> animation ids`; a new mechanism = a row plus a handler in `CatalogStage`), and `OrbitMath` (pure) holds the orbit camera maths. The deploy / raise / traverse / salvo / stow tween steps are `VolleyPlayback`, used by `BattleController._play_volley` and the catalog alike. `tools/screenshot.sh` renders the menu and catalog (`SCREENSHOT_SCENE`, `SCREENSHOT_CATALOG`, see tools/screenshot.gd).

Rocket salvo (TASK-074): `RocketVolley` plays the salvo as a pure function of the salvo time (`update(t)`, driven by one `tween_method`, so the speed scale applies): one rocket per `Mouth*` tube (`UnitView.launch_points` / `launch_directions`, the pod's +X; fallback above the unit, 45° up), launched `SalvoTiming.interval` apart, each on a cubic Bézier (`RocketVolley.path_point`) that leaves along its tube and comes down steeply on a landing point inside the target tile (`SalvoTiming.landing_points`, a view-local RNG seeded from the event serial and the attacker, never `GameState.rng`). Launches and impacts in `(previous t, t]` come from the pure `SalvoTiming.crossings`, so none is skipped or repeated; each fires the signals `rocket_launched(index)` / `rocket_impacted(index, point)` and the effect hooks of `SalvoEffects` (`begin`, `on_launch`, `on_flight` with contiguous segments, `on_impact`, `end`; no-ops in the base class, assigned by `BattleController._play_volley`; TASK-075 fills them). The simple look is a small rocket mesh with a tail glow while the motor burns, launch and impact flashes (`FlashFx`, an additive expanding ball, mesh only, shared with later effects) and a pod jolt per launch (`UnitView.set_launcher_jolt`); no particles, no lights. `VolleyPlayback.connect_hp_steps` steps the target's shown HP (`UnitView.set_shown_hp`) down with every impact (`SalvoTiming.hp_after_impact`, exactly the event's `target_hp` at the last one), plays the hit reaction on the first and the last impact and adds the ground marks at the first.

Sound (TASK-123, no new event types): `AudioDirector` (`src/presentation/audio/`, a child node of the battle created by `AudioDirector.create`) plays what the pure `SoundPlanner` decides (UI action -> id, `fire_sound` of the attacker's `UnitDefinition`, impact: `explosion_large` for a death / `explosion_small` for a hit / none for a direct-fire miss, movement loops `engine_<engine_sound>` + `move_<move_sound>`, `ambient_for(camera_distance, forest_fraction)`). `BattleController` calls it at the same playback moments as the animations, never from `GameSimulation` events directly: the shot when the hit step of the attack plays (`_play_direct_hit`, or the non-turret hit), per rocket from the salvo hooks (`AudioSalvoEffects`, a `SalvoEffects` that wraps the visual effects), the loops for the length of the `unit_moved` tween, `explosion_large` when `unit_died` plays. Sound ids are data: `UnitDefinition.fire_sound / engine_sound / move_sound` and `data/audio/sound_bank.tres` (`SoundBank`: id -> file variants, base pitch, gain, loop, plus the ambient thresholds and polyphony limits). One-shots use a fixed pool of `AudioStreamPlayer3D` (the oldest is stolen), loops a pool of slots that follow the unit and ramp pitch and volume over `SoundPlanner.RAMP_TIME`, the forest loop fades by `ambient_fade` and is re-evaluated only after the camera stopped. Buses (`SoundMix`): Master -> SFX, UI, Ambient; volume and mute are `GameSettings.load_sound / save_sound` (`[sound]` in `user://settings.cfg`), edited in the main menu; a muted or zero-volume game starts no player. Files: CC0 under `assets/third_party/audio/` (ADR 0011 amendment), generated engine / track / wheel loops and rocket launches in `assets/audio/sfx/` (`tools/gen_move_loops.py`); `AudioDirector.hook_tree` adds click / hover / slider ticks to every button and slider under a root (battle HUD, main menu, unit catalog).

Salvo effects (TASK-075): on HIGH (`particles`) `BattleController` creates one `SalvoFxPool` (`src/presentation/salvo_fx_pool.gd`, a `Node3D` child of the battle scene) at battle start and assigns `SalvoFxPool.effects(pool, quality)` to every volley's `effects`; on LOW the pool is not created and `effects` stays the no-op `SalvoEffects` base (the TASK-074 mesh-only salvo). The pool owns five world-space `GPUParticles3D` layers (`fire` 192, `smoke` 256, `blast` 256, `dust` 256, `debris` 128 = 1 088 alive at most) and `TRAILS` 20 reused `SalvoTrail` ribbons; volleys only call `GPUParticles3D.emit_particle()` (position, velocity, colour = tint and opacity, custom = rotation / age / size / lifetime fraction), so no particle node is ever created per volley. The layers are `ParticleFx.puff_emitter`s with custom shaders, not `ParticleProcessMaterial`: `assets/shaders/smoke_particles.gdshader` simulates the puffs (air drag towards the wind drift plus a per-layer rise, gravity for `debris`, ease-out growth; puffs come from `emit_particle()` or, with `emitting`, from its `emit_*` uniforms), `smoke_puff.gdshader` draws sun-lit soft billboards (sphere normal across the quad, the `ParticleFx.billow_texture` grain as self-shadowing, soft fade at the ground) and `fire_puff.gdshader` additive HDR fire; both share `puff_billboard.gdshaderinc`. The vehicle dust and exhaust of `MotionFx` (TASK-064) use the same `puff_emitter` with self-emission (two dust emitters behind the tracks / wheels, one exhaust; a puff keeps the tint it was born with, `ParticleFx.set_puff_tint`). `SalvoTrail` (`salvo_trail.gd` + `salvo_trail.gdshader`) is a camera-facing ribbon through the points the rocket passed while its motor burned (`trail_points`, carry between calls); the shader widens, thins, lifts and drifts each point by its age on the trail's own clock. Its `SalvoFxPool.VolleyFx` implements the hooks: `on_launch` fire at the tube's rear plus smoke (`blast`) and ground dust thrown out behind it (`backblast_origin`, `backblast_dir`) and a trail from the mouth, `on_flight` the motor flame (`salvo_plume.gdshader` cone, `plume_at`: only for `PLUME_TIME` after the launch) and the trail while the motor burns, `on_impact` fireball, dark smoke, dust thrown up (`debris`) and rolling out (`dust`), smoke column puffs and the camera shake sink, `end` hands the target's column to the pool's linger list (`COLUMN_LINGER`, at most `MAX_COLUMNS` fed, fed from `_process`). Per-volley nodes (flame cones, at most two `SalvoLight` OmniLight3Ds, only with `fx_lights`) are children of the `RocketVolley` and die with it. `CameraRig.add_shake` / `shake_strength` move only the camera node (`SHAKE_ENABLED`).

Mesh kit (TASK-030, ADR 0012): `MeshKit` (`models/parts/mesh_kit.gd`, pure geometry, one material) builds chamfered and smooth primitives – `cbox`, `pillow`, `lathe`, `rod`, `bolt`, `stack`, `loft`, `plate`, `profile`, `sweep`, `tube` – in the caller's units (metres), optionally mapped by a `VehicleFrame` and a pivot `base`; `MeshKits` keeps one kit per material role (`k(&"body")`) and `add_to(pivot, materials)` adds one `MeshInstance3D` per material via `ModelParts.add` (pivots that move get their own `MeshKits`). Front faces are clockwise seen from outside (`(v2 − v0) × (v1 − v0)` along the normals). Every primitive writes the **vertex masks** in `ARRAY_COLOR` (8-bit), the contract with the paint shader: Levels of detail and render rules (ADR 0023): `ModelParts.cached` runs every model prototype through `MeshLods.apply` (`models/parts/mesh_lods.gd`), which indexes each mesh of 64+ triangles and generates coarser levels for kit geometry (position-welded simplification per error of `LEVEL_ERRORS`, primitives under a pixel dropped, corners mapped back to original vertices so the colour masks hold, folded thin plates kept finer; per mesh the better of this and `ImporterMesh.generate_lods`; shown at half a pixel of error; cached in `user://cache/mesh_lods.bin`). The renderer picks the level per instance, so model files need no LOD code. `UnitRenderRules` (`unit_render_rules.gd`) states what a model may cost: materials that stay in the opaque pass and need no full-screen pass (`material_violations`: no alpha beyond a scissor, blending, subsurface scattering, refraction, screen / depth reads, fades, `next_pass`) and at most `MAX_FAR_TRIANGLES` 20 000 in the default battle view (`far_triangles`); `tests/unit/test_unit_model_contract.gd` checks both for every model and faction (violation key `render`), `tools/render_unit.sh` prints them.

| Channel | Meaning | Written as | Paint use |
|---|---|---|---|
| `r` | chamfer / edge | 1 on chamfer bands, box corners, plate rims, short diagonal lathe segments (< `chamfer_max`), tube end caps; 0 on faces | paint wear |
| `g` | openness | the kit's `openness` (1 = open, set lower by the model for recessed parts), × `INNER_OPENNESS` (0.35) on a lathe's inner wall | cavity darkening |
| `b` | per-part tint seed | `MeshKit.tint_seed(part centre)` – hash, constant per primitive call, deterministic | per-part tint |

## Graphics quality

`GraphicsQuality` (`src/presentation/graphics_quality.gd`, pure static) picks the LOW/HIGH preset (`detect` from renderer + adapter, `--quality=` override via `parse_override`) and holds the feature switches (`features`); `BattleController` applies them to the environment/sun/viewport (shadows, MSAA, 3D render scale) and passes `quality` to `MapView` (LOW: no foliage scatter) / `UnitView`.

`ColorGrade` (`src/presentation/color_grade.gd`, pure static, TASK-051) is the muted/olive colour grade: `grade(c, params)` and `lut(size, params)` bake a 3D LUT (`cached_texture()`, built once); `GraphicsQuality.apply_environment` assigns it as `adjustment_color_correction` on HIGH (feature `color_grade`) and disables adjustments on LOW.

HUD v3 building blocks (TASK-076, ADR 0013, `src/presentation/ui/`): `UiPalette` (tokens), `HudTheme` (`display(weight)` Chakra Petch, `mono(weight)` JetBrains Mono), `HudShapes` (pure chamfer / hex / tab / hatch / ruler geometry), `FramedPanel` (chamfered 1 px frame + header tab + brackets, a `MarginContainer`), `HatchBar`, `Bracketed`, and `ScreenDecor` (vignette + scanlines + corner brackets in one shader, first child of the HUD root).

## Chunked world

The battle scenery exists only near the camera (TASK-072b, ADR 0024). `ChunkManager` (`src/presentation/chunk_manager.gd`, a `RefCounted` owned by `MapView`) keeps a set of live chunks per registered `ChunkLayer`; a layer is three callables – `plan_chunk(chunk) -> Variant` (pure, runs on the `WorkerThreadPool`), `build_chunk(chunk, plan)` and `free_chunk(chunk)` (main thread) – plus its chunk size, origin, area and an optional main-thread `prepare` that fills the lazy caches the planners read (`MapView.prime_surface`, `FeatureRibbonPlanner.is_clear`, `TreeField.prime_sizes`). Rings are data: `ChunkRings` (`data/visuals/chunk_rings.tres`) gives each layer id a draw reach in metres (converted with `MapScale`) around the camera target; chunks within 1.5 × the reach are built nearest first, built chunks beyond 1.2 × the build ring are freed (hysteresis), LOW multiplies every reach by 0.66 (`GraphicsQuality` `small_chunk_rings`). `MapView.set_camera_target` rescans after 2 units of movement (or a quarter of the smallest enabled build ring, TASK-134); `ChunkManager.set_enabled(id, on)` switches a layer off (everything built freed, nothing built) and on; `MapView._process` → `ChunkManager.process()` frees chunks beyond the free ring for up to half the budget, collects a finished worker batch (24 jobs, planned by at most cores − 2 threads at normal priority so the main and render threads keep a core each), starts the next and builds planned chunks for at most `budget_usec` (4 ms) per frame (the first chunk of a frame always runs, the rest only while the running average of that layer's build cost fits), the queue carries over; `finish_chunks()` builds everything at once (loading screen: `BattleController._prebuild_chunks` with a 50 ms budget per frame; tests, screenshots, the bench). `invalidate(id, rect)` rebuilds the chunks a change touches (grass clearings). A plan depends on the chunk alone, so the build order and the thread count never change the result (tested). Layers: `terrain` (`TerrainChunks`), `terrain_near` (`TerrainNear`, TASK-134), `scatter` and `trees` (`FoliageChunks`), `grass` (`GrassField`), `grid` (MapView's grid lines) and `marks` (`GroundMarksView`, registered by `BattleController`: decals of a freed chunk are hidden, not dropped). New layers (TASK-134 terrain LOD, TASK-135 impostors) register the same way. A layer may be `instant` (TASK-189: no worker plan – the GPU-placed forest impostors, one node per chunk; its new chunks are built on the main thread nearest first by the scan and then by `process()`, each within `instant_budget_usec`, 4 ms) and carries a `priority` (queued jobs of a higher priority are planned first, nearest first within a priority: the full trees before the near grass). A layer with `reach_m` > 0 (TASK-217a: the GPU-placed shrubs, whose reach is a look value capped by the quality) uses it instead of its `ChunkRings` entry (build ring = reach × `build_factor`, no LOW factor).

## Terrain rendering

`MapView` builds the terrain as chunks of one global vertex lattice (`TerrainLattice`: 4 vertices per world unit, 32 × 32 cells = 8 × 8 units per chunk, heights from `TerrainSurface` as a pure function of the vertex index; odd vertices of the outer border lie between their even neighbours for the backdrop seam). `TerrainChunks` plans a chunk's arrays on the worker threads (normals by central differences, `TerrainSplat` weights smoothed over the neighbours, both computed from the lattice two vertices beyond the chunk, so neighbouring chunks agree on every shared vertex; a 0.4 unit skirt hangs from each edge and hides the slivers against coarser neighbours). Near the camera a chunk is drawn at full resolution (`Terrain/Terrain_<x>_<z>`, the `terrain` ring); every chunk also has a coarse mesh (every 4th vertex, no shadows) built up front, 4 × 4 chunks per node (`TerrainFar/TerrainFar_<gx>_<gz>`) whose index buffer leaves out the chunks with a fine mesh, so the whole map always shows. **Near LOD** (TASK-134, ADR 0025): `TerrainNear` draws the ground within the `terrain_near` ring (433 m reach = 3 units) at 8 × the lattice resolution (1/32 unit = 4.5 m) in chunks of 1 × 1 unit (`TerrainNear/TerrainNear_<x>_<z>`, 33² vertices, shadows on); a built near chunk punches its 4 × 4-cell block out of the fine chunk under it (`TerrainChunks.set_hole`: a fine chunk's index buffer is kept per block, with each block's skirt quads). Inner near vertices sample `TerrainSurface` (the function the core tile heights come from); each edge has a planned "raw" (surface) and "fine" (lattice edge interpolated) variant – raw where the neighbouring near chunk is built, fine where the fine mesh continues, switched on the main thread when a neighbour is built or freed – so the ring border lies exactly on the fine triangles' edges (tested ± 1 mm) and a 0.02 skirt covers the T-junction slivers. Weights, tints and the fine-edge normals are the lattice's own per-vertex values (`TerrainChunks.vertex_attributes`) interpolated on its triangles. The layer is on while the camera distance is ≤ 12 units (off beyond 14) and only on HIGH (`GraphicsQuality` `terrain_lod`); `TerrainNear.drawn_height_at` is the drawn near surface (TASK-136). `MapView.mesh_height_at` reads the lattice's height blocks, computed after 48 queries into a block and kept (thread-safe, one thread per block; fewer queries read the four cell corners directly). Plus the backdrop ring (`BackdropMesh`, TASK-052; the map terrain it copies along the border comes from `BackdropTypes`, cached per border vertex), both drawn with one `ShaderMaterial` on `assets/shaders/terrain.gdshader` (`TerrainGround.material`, TASK-055):

- **Layers**: six CC0 ground materials (`assets/third_party/textures/ground/<layer>/`, credited in `credits.json`) in a fixed order: `0 grass`, `1 dry_grass`, `2 dirt` (also forest floor), `3 mud`, `4 gravel`, `5 rock`. `TerrainTextures` (static) decodes and packs them on the `WorkerThreadPool` while the mesh is built into two `Texture2DArray`s – `albedo_height` (RGB albedo, height in A) and `normal_rough_ao` (RG normal x, y in OpenGL convention with z rebuilt in the shader, B roughness, A AO; trilinear, only the albedo is filtered anisotropically) – size from `GraphicsQuality.features` `terrain_texture_size` (HIGH 1024², LOW 512²), cached per size.
- **Weights**: `TerrainSplat.weights(terrain, slope, height, water_level, moisture, macro)` (pure, static, `tests/unit/test_terrain_splat.gd`) gives six weights summing to 1 per vertex (plains: grass/dry grass by macro noise + dirt patches; forest: dirt floor; fields: dry grass 0.4 / dirt 0.15 / grass 0.45 (the parcels below paint over it); urban: gravel 0.5 / dirt 0.3 / grass 0.2; marsh: grass 0.55 / mud 0.45 – TASK-108; rock/gravel by slope and on high ground; mud/dirt shore band 0.12 above the water; water beds mud), then `TerrainSplat.smooth` averages neighbours within one mesh step. Layers 0–3 are stored in `ARRAY_COLOR` (8-bit, quantised so the sum stays within ±0.01), 4–5 in `ARRAY_CUSTOM0` (RGBA float, `TerrainGround.add_surface`; `.zw` free for TASK-108b field / road ground layers). `ARRAY_TEX_UV2` carries a value/saturation factor (darkened off-map margin, muted backdrop).
- **Roads and rivers** (TASK-108): `FeatureRibbonPlanner` (pure, cached per grid and `links_version`) turns the per-tile link masks into smooth centrelines instead of hex zigzags. Pieces per tile: the two most opposite links form a through piece (side midpoint to side midpoint), further exactly opposite pairs cross it, remaining links are spokes ending on the first through piece's midpoint (a junction), a lone link is a dead end at the centre. Pieces sharing a side midpoint are chained into one polyline (ends: spokes, dead ends, ports without partner = map edge / shore; loops are kept). Each piece is a cubic Bézier with Catmull-Rom-like tangents at the ports (previous to next port, at most 50° off the side normal; the same tangent on both sides of a port, so no kink) and inner control points clamped inside the hex, so by the convex hull property the line stays in its tile and crosses the linked side. Rivers (`RiverShape`, TASK-108c follow-up; all lengths metres via `MapScale`): a clear meander (up to ±32 m along the normal: a 24.5 m swing at 317 m wavelength plus a 7.5 m wobble at 108 m, value noise of the world position; kept 0.06 units from walls the piece does not cross, calmed within 130 m of confluences) and independent irregular banks (per-side water edge ±25 % and bank band ±50 %, each a slow plus a fast noise, `RiverShape.edge_noise`) and a real width (TASK-108c: 8 m of water ± 25 % by noise, narrowing to 40 % towards a dead-end source, plus a 3 m bank band on each side – one ribbon, `across` 0 on the centreline and ±1 at the bank's outer edge); roads at their real width (TASK-108b: 5 m carriageway + 2 × 2.5 m verge, `MapScale`) with a round disc at junctions and dead ends. Strips: an indexed mesh (`FeatureRibbonPlanner.mesh`: points + clockwise triangles; `triangles` expands it) with per-vertex side offsets from the neighbouring vertices (neighbouring quads share corners: no gaps, overlaps or spikes), samples every ~0.06. `FeatureRibbons.build` drapes it on the terrain mesh (`MapView._drape`; river +0.02, road +0.024 so it reads as crossing the river; plus a crest lift per point – twice the largest height the terrain rises above a triangle at its edge midpoints and centroid, the maximum over the triangles sharing the point – so ribbons do not dip under the terrain mesh's convex creases) as **one** `MeshInstance3D` per kind (`Roads`: `road.gdshader`; `Rivers`: `river.gdshader`, see below; plain-material fallbacks `#8a7f6a` / `#3d5a66` without a ground material) – none when the grid has no links (generated maps). Trees, rocks, bushes, grass and flowers keep the local half width + 3 m clear of the same centrelines (`FeatureRibbonPlanner.is_clear` / `edge_distance`: a per-grid index of the centreline pieces near each tile; scatter is filtered after planning so the RNG streams are unchanged).
- **River water and bridges** (TASK-108c): `FeatureRibbonPlanner` stores every river line downstream-first (`flows(grid)` = arc length in metres from the upstream end per vertex, parallel to `lines`): a chain flows from its end with the higher drawn ground (`TerrainSurface`) to the lower; ends within 1.5 m (vertical metres taken 1:1 with `MapScale`) flow from a dead-end source, else from the smaller (x, z); loops keep their order. `mesh(grid, RIVER)` additionally returns `along` (→ `UV.x`), `water_edge` (the `across` value where water ends and the bank starts, per vertex and side → `COLOR.r`) and `fade` (→ `COLOR.g`, opacity factor 0..1: 0 at a source and where a tributary ends on the through river, rising over 9 m / 12 m, so a confluence reads as one body of water; tributary strips are drawn after the through river); `FeatureRibbons.build` adds tangents (+x) for the normal map. `assets/shaders/river.gdshader` (Compatibility-safe, one `MeshInstance3D` `Rivers`, `render_priority` -1 so it draws below the road ribbon): water from deep `#2e4a52` (centre, alpha 0.95) to shallow `#4c6a62` (water edge, alpha 0.7), roughness 0.06, `water.gdshader`'s normal map sampled at (`along`, `across` × half width) in metres at two scales scrolled downstream at 0.4 m/s (`flow_speed`; GraphicsQuality `river_flow`: HIGH on, LOW 0 = static), the bank is the mud ground layer (sampled like the road's gravel) fading to alpha 0 at the outer edge, and the vertex shader keeps the water at least 1.5 px wide on screen. `FeatureRibbonPlanner.bridges(grid)` finds every crossing of a drawn road centreline and a drawn river centreline (segment tests per tile on the clearance index, sites closer than 10 m merged): `{position, direction, span_m, water_m, width_m}`, `span_m` = `bridge_span_m(water, |sin angle|)` = water / |sin| + 2 × 4 m abutments, capped at 40 m, 7 m wide; a road link into a river hex whose drawn line misses the river gets none. `Bridges.build(sites, drape, shadows)` makes **one** merged `ArrayMesh` node `Bridges` (deck in two halves meeting 1.5 m above the water at mid-span and the road ribbon height at the ends, two railings, two abutment blocks; ≤ 60 triangles per bridge; concrete grey `#8d8b84`, roughness 0.9; shadows follow `GraphicsQuality.shadows`); `FeatureRibbons.add_to` adds roads, rivers and bridges to the map (no `Bridges` node without sites). No rule changes: the +1 river step cost of TASK-108 is unchanged.
- **Farmland parcels** (TASK-108f, imported real-terrain maps only): `FieldParcels` (pure, metres via `MapScale.metres_per_unit`, integer hash, never `GameState.rng`) cuts the land into 2.5 km regions with one hashed orientation each (along x or z), parallel strips of 150–400 m and up to 2.5 km long (10 % cut in two, parts at least 800 m), with a 10 m balk along each strip's long edge and across both ends (so a region border is a hedge, not a bare seam); each parcel gets one crop by hash from the shares in `LookPreset.fields()` (wheat 24, maize 10, potato / beet 10, young cereal 16, stubble 15, ploughed 16, meadow 9 %: greens ~45 %, muted olive / grey-green tones – plant / furrow colours, row spacing in m, plant width, `grass_keep`: look data, a preset may override). A strip is judged in pieces of at most 150 m (`SEGMENT_M`; gaps of up to 2 non-farmland pieces, about one hex, are bridged): a piece is farmland when at least half of its 40 m lattice samples lie on FIELDS tiles, so a strip runs as far as the farmland does and ends in a straight cut (majority rule: it spills over neighbouring plains / hills; hexes only decide, they never show). `FieldParcels.bake(grid, hex_size, rect)` returns a `ParcelMap` (RG8 image at 5 m / px over the map plus `MapView.PARCEL_MARGIN`: red = kind, green = parcel id × 2 + row orientation; ~220 ms on Suwałki, `null` when the grid has no FIELDS tile) with FOREST / WATER / URBAN / MARSH tiles cleared by hex scanlines. `TerrainGround.set_parcels` feeds it to the terrain shader (`parcels_on`, one nearest sample): the crop colour replaces the splat albedo with world-space row stripes across the parcel orientation (filtered by `fwidth`, fading to the average colour when a row is under ~0.3–0.8 px), per-parcel brightness / hue variation and patch noise, faded out on slopes steeper than `GrassPlanner.MAX_SLOPE`, rock and mud. Nothing stands on a parcel: `ScatterPlanner.plan(…, parcels)` drops every tree, bush, rock, shrub, undergrowth and thicket on any parcel kind except the balk (after planning, so RNG streams and positions elsewhere are unchanged; also for the backdrop ring plan), `GrassPlanner.plan_chunk(…, parcels)` multiplies the keep chance by the crop's `grass_keep` (0 on every crop, 1 on meadow) and `plan_flowers` skips crop parcels (meadows keep short grass and flowers). `ScatterPlanner.plan_hedges` plants copses (shrubs, some trees) on the balk of about half of the strips by position hash. `BackdropCanopy` (distant forest shell) is not parcel-aware: it follows the border forest share only. Follow-up: 3D crop stalks near the camera.
- **Real field parcels** (TASK-215b, ADR 0032; `true` VisualScale preset, imported maps with OSM parcel polygons; look numbers in `RealParcelLook`, `data/fields/real_parcels.tres`): `BattleCover.parcels_for_battle` builds a `RealParcels` (pure, integer hash of the map id and polygon id, never `GameState.rng`) from `ImportedMap.parcel_polygon` / `parcel_edge_kinds` / `parcel_landuse`: polygons over `large_parcel_ha` (5 ha) are cut perpendicular to their long axis (min-area rectangle) into ceil(area / 5 ha) parcels of equal area (Sutherland-Hodgman slabs, holes kept); rows run along a parcel's long side (20 % across, by hash). In the bake (`FieldParcels.bake(…, look, real)`; no strips are painted under it) `RealParcels.paint` first fills the open land without a polygon (`ParcelFill`): field systems = convex Voronoi cells of a jittered `fill_cell_m` grid, each with the direction of the nearest OSM parcel (else hashed), split recursively across the longer side into ~`fill_target_ha` parcels, kept where some of the parcel may show (`CoverLook.allows_parcel`), with hedges on a share of the system borders and splits. All pieces are scanline-filled into the RGB8 label image (red kind, green variation id × 2 + 1 for OSM, blue 1 + row angle; the OSM parcels over the fill), neighbours come from the pixel spans, crops are assigned in smallest-last order (bucket queue) so that no neighbours share one. `RealParcels.edge_image` (row bands on the worker threads) writes `ParcelMap.edges`, a 10 m RGB8 image where every texel within `EDGE_RANGE_M` (15 m) of a parcel edge holds its nearest edge as an exact line (angle code, signed distance, edge kind; tracks and hedges win over the plain edge they lie on; the fill's edges are left out under OSM parcels). The shader's `parcel_label` (CPU twin `ParcelMap.label_at_metres`) takes, next to an edge, the label 1.5 label texels beyond the exact line on the point's side, BALK within the half width of a hedge (`BALK_M`) or track (`track_m`) edge, and the headland along every edge – straight edges at every zoom. `ParcelMap.hedge_lines()` gives the hedge polylines; `ScatterPlanner.plan_hedges` plants tree lines (trees and shrubs every `hedge_step_m`) on them. A real parcel is masked by the land cover only where no field can be (`allows_parcel`: not forest, water, village or marsh; shader `in_cover(xz, COVER_PARCEL_MASK)`). The crops get coarse stripes along their rows (`CropKind.stripe_m` / `stripe_contrast`: tramlines, swaths, furrow bands, readable at mid zoom), and a real parcel takes only `satellite_hue` of the satellite layer's hue at every distance (its own luminance, edges and contrast stay) with `crop_tint` / `crop_saturation` of the resource. Without polygons, and under `balanced`, the bake is byte-identical to before (`tests/unit/test_real_parcels.gd`).
- **Shader**: world-space sampling at `layer_repeat` (TASK-134: the layer's real scanned size, 1.3–3 m, through `MapScale` – `TerrainGround.layer_repeats` – cross-faded by view distance 2.5 → 6 units to `layer_repeat_far`, 75 × that size, the pattern that reads from the default zoom; roads use the far pattern only), a ground detail texture close to the camera (`TerrainGround.detail_texture`: procedural normal + height, 24 m repeat plus a rotated 7.2 m sample, ±30 % albedo, a drier tint and a normal tilt, faded in by view distance from 6 to 4 units; `terrain_detail`, HIGH only), height blending (`w + h − max + 0.2`), roughness remapped to `[roughness_min, 1]`, AO, ±8 % low-frequency macro brightness, darker lake beds by depth. Uniforms `anti_tiling` (second sample ×3.7, rotated 37°, mixed by noise) and `triplanar` (rock on steep slopes) come from `GraphicsQuality.features` (`terrain_anti_tiling`, `terrain_triplanar`: HIGH only).
- **Satellite colour** (TASK-192b, ADR 0031; `true` VisualScale preset only): `BattleCover.colour_for_battle` gives `MapView.satellite`, a `SatelliteColour` – one sRGB texture (mipmapped, anisotropic) over the battle's world rectangle: the imported map's whole `ColourRaster` (10 m), or a tactical layer cut sampled from its 40 m chunk windows under the region plus `BattleCover.MARGIN`. `SatelliteColour.apply` feeds `assets/shaders/satellite_colour.gdshaderinc` (included by `terrain.gdshader` and `canopy.gdshader`) with the values of `LookPreset.satellite()` in metres through `MapScale`: the ground keeps its splat / parcel / detail colour with a luminance-preserving tint of `near_tint` (0.25) towards the layer's hue up to `blend_start_m` (300 m view distance), and the layer's own colour takes over by `blend_end_m` (1500 m) (smoothstep; applied after the macro brightness, before the off-map margin factor, lake bed and cloud shadow); the layer fades out over `edge_m` inside its raster's edge (backdrop beyond an imported map's raster keeps the textured look). The canopy shells (`ForestShell`, `BackdropCanopy`) take the layer's hue at the crown's own luminance by the same distance weight × `canopy_hue`, so the dome shading and the impostor-matched brightness stay. Off (`satellite_on` false, the shader default) for `balanced`, generated maps and maps without a layer: the branches are skipped and the output is unchanged. GDScript twins of the weight / tint functions: `SatelliteColour.weight` / `ground` / `canopy` (`tests/unit/test_satellite_colour.gd`).

## Grass and wind

Grass (TASK-057) is cosmetic and fully in the view layer. `GrassPlanner` (pure, static; hash-seeded RNG, never `GameState.rng`) plans the clumps of one 4 x 4 world-unit chunk (`plan_chunk`): density per terrain (plains 90, hills 50, forest 25 per unit², none on water, the shore band or slopes above 0.5), scaled by the quality `grass_density`. `GrassField` (a `Node3D` owned by `MapView`) builds one `MultiMeshInstance3D` per chunk as the `grass` layer of the chunk manager (build ring 20 units around the camera target; the clumps, their ground colours and the MultiMesh buffers are planned on the worker threads) and frees it beyond the free ring. Chunks use `visibility_range_end` 14 with a 3 unit margin and `VISIBILITY_RANGE_FADE_SELF`, so grass fades out with distance (measured from the chunk centre) and costs nothing far away; they cast no shadows. The total is capped at `GrassPlanner.INSTANCE_BUDGET` (the density is cut back if the map – or, when smaller, the free ring's area – would exceed it). `GrassMesh` is the 3-card clump, `GrassTexture` a procedural neutral grey blade card; the hue is the per-instance colour, the mean linear albedo of the `TerrainSplat` layers (`TerrainTextures` `average_colors`) weighted like the terrain shader, cached per 0.5 unit cell. Clump size is `0.07 x 0.05 x VisualScale.grass_scale()` (the `grass_scale` key follows the preset's `bush_scale`).

Open-ground vegetation (TASK-070). All tunables are look data: `LookPreset.meadow()` returns `MEADOW_OFF` (every feature off – the `current` preset reproduces the TASK-057/061 output exactly) merged with the active preset's `"meadow"` entry; planner functions take that dictionary as an argument (empty = the active one). `GrassPlanner` clumps carry `kind` (`Kind.SHORT / TALL / DRY_STALK / NETTLE`) and `height` (vertical multiplier, at most 1.5 in any preset). The kind comes from noises in world space (`GroundNoise.macro_k` for dry areas = the dry grass of the ground texture, `patch_k` for tall-grass patches, `moisture_k` for the bare dirt patches that also thin the grass) and from position hashes (`GrassPlanner.hash01`), never from extra RNG draws, so the TASK-057 positions do not move; forest edges (`forest_edge_distance`) get a tall-grass bonus and nettle, a radius around each tile centre stays short grass so units remain readable. `GrassPlanner.kind_color` blends the ground colour towards the kind's colour; `GrassField.clump_transform` scales the instance `(s, s * height, s)` and `GrassField.max_clump_height()` (used by `GroundOverlay.depth_pull()`) includes the tallest multiplier. Meadow flowers: `GrassPlanner.plan_flowers` (own RNG stream, seven draws per candidate) places small single-species clusters on plains (and sparsely on hills); `GrassField` builds a `Flowers_<x>_<z>` `MultiMeshInstance3D` next to each grass chunk (same clump mesh, `GrassTexture.flower_card`, `grass.gdshader` with `flower_mode`, same ranges, no shadows) and `instance_count()` counts both; the budget estimate reserves a flower share. LOW builds neither. Riparian vegetation (TASK-108c follow-up): `RiparianPlanner.plan(grid, surface, parcels, rect, look)` (pure, position hashes only, same chunk contract as `ScatterPlanner.plan_hedges`, called from `FoliageChunks._plan_source`, nothing without river links) adds a patchy belt of shrubs (3.5-17 m beyond the ribbon edge) and alder trees (5-21 m), at most 110 shrubs / 28 trees per tile, none on URBAN, forest or water tiles, parcels, or the ribbon clearance. Reeds (TASK-108e): `Kind.REED` (appended; height `reed_height` 1.5, so `max_clump_height()` is unchanged). `GrassPlanner.is_reed` picks them with position hashes only: on marsh where `GroundNoise.reed_k` (the patch noise at its own offset and `reed_seed`) exceeds `reed_from` (0.35, about 70 % of marsh clumps away from the tile centre, times `reed_share`), and on any land except URBAN within `reed_band_m` (10 m, converted by `MapScale.to_units`) of a river edge (`FeatureRibbonPlanner.edge_distance`) with probability `bank_reeds` 0.7. Marsh is denser by `marsh_density` (1.3): the surplus candidates come from their own RNG stream (`MARSH_SEED_SALT`) and only count on marsh, so the TASK-057 stream and every non-marsh chunk are untouched; `GrassField._estimate` counts the surplus for the budget. `MEADOW_OFF` has `reed_share` 0, `bank_reeds` 0, `marsh_density` 1 (the `current` look has no reeds); the summer presets set `reed_color` `#6f7a45` towards `reed_dry_color` `#a39466` by `GrassPlanner.dry_k` (passed to `kind_color`). `GrassField` builds reeds as a third node per chunk (`Reeds_<x>_<z>`, `GrassTexture.reed_card`, `grass.gdshader` with `reed_mode`: blades grey and tinted, brown seed heads R > B left untinted), counted in `instance_count()` and `reed_nodes()`. `MapScale` (pure static, `metres_per_unit`, default 250 / sqrt(3) = 144.34 m = the Suwalki scale) is the shared metres-to-units converter for the 108x tasks.

Ground overlays (unit marker rings and fills, reach / range / attack / hover washes) are lower than the grass, so they all use `GroundOverlay.material` (`assets/shaders/ground_overlay.gdshader`): the vertex shader pulls them towards the camera along the view ray by `GroundOverlay.depth_pull()` (tallest clump height / sin of the closest default camera pitch). The screen position is unchanged, only the depth, so overlays draw over the grass but stay hidden behind trees, units and ridges. Only rings and outlines get the pull; fills (`GroundOverlay.material(color, false)`) keep normal depth, because they lie under the unit models and a pull would tint the lower half of a model; they are `ground_only` instead – the shader compares the fill with the scene depth reconstructed to world Y and tints only the terrain, not wheels, tracks, boots or grass standing in the fill.

`Wind` registers the global shader parameters `wind_direction`, `wind_strength`, `wind_speed` at runtime (`RenderingServer.global_shader_parameter_add`, not in `project.godot`; strength 0 when the quality's `wind` is false). `assets/shaders/wind.gdshaderinc` reads them (`wind_offset`) and is shared by `grass.gdshader`, `foliage.gdshader` (trees, which also use its `wind_flutter`) and the later undergrowth shader. Under the headless dummy renderer the globals do not exist, so tests only check `Wind.strength()`.

## Trees

Trees (TASK-060) are cosmetic and view-only; `ScatterPlanner` still plans them (placement, counts and the high-ground conifer rule unchanged). `TreeSpecies.pick(tree)` (pure, static, a hash of the planned `position` and `k`, no RNG object) turns a planned tree into `{species, variant, custom}`: conifers become pine (60 %) or spruce (40 %), the others birch (35 %), oak (30 %) or alder (35 %); `custom` is the instance's `INSTANCE_CUSTOM` (r hue shift +-0.03, or +0.04..0.07 on the 1 in 25 yellower "autumn" deciduous tree; g value x0.85..1.1; b saturation x0.9..1.05; a wind phase). `TreeMeshes` (pure, cached, deterministic from `(species, variant)`, 3 variants per species, base at y = 0) builds one `ArrayMesh` with one surface per tree (TASK-108; bark first, then leaves): bark (a tapered lathe trunk closed by a cap inside the crown, tapered branch rods) and leaves (LOD0: 60-120 alpha-scissor cards for deciduous crowns on lobes at the branch tips, 40-100 needle cards for conifers – spruce in drooping whorls, pine as flat tufts on short upper branches; LOD1: three jittered icosphere lobes with the hidden triangles dropped, or a cone stack). Crown normals are bent outwards from the crown centre; vertex colour r = AO, g = per-card flutter phase, b = 1 on leaves / 0 on bark. LOD0 is 230-341 triangles per tree on average per species, LOD1 26-155. `LeafTexture` paints the neutral-grey cards (`cluster` for leaves, `needles` for conifers; alpha 0/1, procedural – no CC0 textures are used).

`TreeField` (a `Node3D` owned by `MapView`; its chunks are the `trees` layer, planned by `FoliageChunks` from `ScatterPlanner.plan_rect` – the tiles whose centre lies in the chunk, every tile seeding its own RNG streams – and `TreeField.plan_chunk`, which also packs the MultiMesh buffers on the worker thread) groups the map and backdrop trees into 8 x 8 unit chunks and makes one `MultiMeshInstance3D` per chunk x species x variant x LOD that has instances, origin at the chunk centre. Three tiers, all shadow casting (the card shadows are alpha-scissored). The tiers hand over **per tree in the vertex shader** (ADR 0023): each material carries the bands `lod_in` / `lod_out` (`TreeField.lod_bands`, distance of the tree's base from the main camera), a tree switches at its own random point of the band (`INSTANCE_CUSTOM.a`, the same in every LOD) and the LOD that does not draw it collapses it to a point, so a stand changes gradually and no tree is drawn twice; the nodes' visibility ranges only cull whole chunks (`RANGE_SLACK` 8 wider than the bands, no `FADE_SELF` – Godot draws fading instances alpha-blended without the depth prepass). LOD0 (cards, per variant, `foliage.gdshader`) up to 30, margin 4; LOD1 (one solid mesh per species, `foliage_solid.gdshader`: fully opaque, no wind) from 30 (margin 4) – for trees up to `TreeField.LOD2_DISTANCE` 46 (margin 4), for scrub to the horizon; LOD2 (trees only, `TreeMeshes.lod2`: LOD1 with subdivision-0 lobes, 5-sided cones, 3-sided trunk, ≤ 70 triangles) from 46 (TASK-108; at the default camera only zoomed-out views reach it). Backdrop trees more than `BACKDROP_LOD0_REACH` (14) units outside the playable tiles get only a "far" LOD1 node without a range: that keeps the LOD0 triangles of all chunks within 41 units (30 + 4 + `CameraMath.CLOSE_RANGE_DISTANCE` 7, the closest zoom before TASK-111; closer zooms keep the camera nearer its target) of any playable tile centre under 1 100 000 (default map: ~1 050 000 with scrub, was ~702 000 before TASK-061; tested). Instance size is `VisualScale.tree_scale()` (`TreeField.tree_transform`). LOW (`foliage = false`) builds no trees. `assets/shaders/foliage_body.gdshaderinc` (included by both shaders; one material per species and LOD) shades both parts: species leaf colour shifted per instance in HSV, alpha scissor 0.5 on the cards (no alpha antialiasing: it would move the trees into the alpha pass, without the depth prepass), `BACKLIGHT` 0.35 x leaf colour, bark with procedural streaks (birch: light with dark marks); wind: the whole tree sways with `wind_offset(instance origin, y / 0.3, phase)` and leaf cards flutter with `wind_flutter` (at most 0.003 world units), both from the shared include. Scrub (TASK-061: species `shrub` and `undergrowth`, planned by `ScatterPlanner` as `edge_shrubs` / `ground_cover` with a `species` key, built from `TreeMeshes.SCRUB`) goes through the same field with shorter LOD0 ranges (`TreeField.SCRUB_LOD_DISTANCE`); undergrowth and backdrop trees cast no shadows; the wind only moves trees within `wind_distance` (24, faded over 8) of the camera, LOD1 crowns not at all. Thickets on open ground (TASK-070: a shrub with two undergrowth plants at a tile border, `ScatterPlanner.plan_tile_meadow`, output key `meadow_scrub`, own RNG stream, map tiles only – not the backdrop – and absent under `current` or on LOW) go through the same field. Bushes and rocks still use `FoliageMeshes`, built by `ScatterChunks` (TASK-108) as one parent node per kind (`Bushes`, `Rocks`, `BackdropBushes`, `BackdropRocks` under the tiles root) with one `MultiMeshInstance3D` per 8 x 8 `TreeField` chunk, named `<name>_<x>_<z>` (origin at the chunk centre, frustum culled, no shadows); bushes also get `<name>Far_<x>_<z>` nodes with `FoliageMeshes.bush_far` (one lobe subdivision coarser, 400 instead of 1600 triangles): near nodes end and far nodes begin at `ScatterChunks.BUSH_LOD_DISTANCE` 16 with a hard switch (`BUSH_LOD_MARGIN` 2 is only its hysteresis; no `FADE_SELF`, see ADR 0023). `BurntGround` recognises rock chunks by the `Rocks` name prefix. Performance on large maps (TASK-108): `TreeMeshes` puts bark and leaves into **one** surface (one draw per node and pass; the shader tells them apart by vertex colour b, `TreeMeshes.part_arrays` splits them for tests); scrub LOD1 (shrub, undergrowth) uses the three LOD1 lobes as plain jittered icosahedra (`SCRUB_LOD1_LOBE_SUBDIVISIONS` 0, ~60 instead of 155 triangles); coarse (subdivision 0) lobes drop a triangle only when all three of its corners lie inside another lobe – dropping by the midpoint opened see-through holes that made the shrubs look smaller and paler. Distant forest: real backdrop scatter only within `MapView.BACKDROP_SCATTER_REACH` (4) of the playable mesh; beyond it `BackdropCanopy` draws a cheap shell over the backdrop lattice (forest share of the nearest border tiles as vertex colour r, faded in over 1.5..5 units) with `assets/shaders/canopy.gdshader`, which paints jittered Voronoi crowns in the species colours (a crown is dropped when its hash exceeds the cover, so edges are ragged). `tools/screenshot.sh` can aim at a world point (`SCREENSHOT_FOCUS=<x>,<z>,<yaw>,<distance>`) and time frames (`SCREENSHOT_MEASURE_FRAMES=N` prints `Frame time: avg X ms, max Y ms over N frames` and `Render: draws, tris, GPU ms, render CPU ms`, vsync off and the 60 FPS `FramePacing` cap lifted during the timed frames).

**Real-scale vegetation** (TASK-135, ADR 0026; only under the `true` `VisualScale` preset – `balanced` is unchanged): `RealScaleVegetation` (owned by `MapView`) adds a second, camera-centred `ChunkManager` (`MapView.set_camera_position`, fed from the viewport camera in `_process`) and three pieces. `ForestFill` plants ~2 000 visual trees per forest hex (`LookPreset.vegetation()` `forest_trees_per_ha` × the `MapScale` hex area) on a hash-jittered world grid: every tree is a pure function of its grid cell (32-bit integer hashes of seed, cell and salt give point, size, species, variant and colour; no RNG, no draws from ScatterPlanner's streams), standing where one stand mask allows (L8, 32 texels per unit ≈ 4.5 m, built once per map from a `ForestMaskSource`: forest land cover minus the tile-centre clearing and the road / river ribbons; today `HexForestMaskSource` from the FOREST tiles – hex-edged, transitional until TASK-108g's land-cover raster becomes the source), off the `ParcelMap` parcels and above the shore (the drawn lattice height). `ForestField` draws them as full LOD0 trees (`forest_full`, 1-unit chunks on the camera manager, planned on the worker threads from the `ForestFill` reference, standing on the drawn near triangles) to 250 m × species height / 24 m and as GPU-placed impostors (TASK-189, ADR 0027: `forest`, an `instant` layer of 2-unit chunks on the target manager; a chunk is one node sharing one MultiMesh of the `TreeImpostors` quad with one instance per fill cell and no instance data, its cell range an instance uniform; `forest_impostor.gdshader` derives each tree from `INSTANCE_ID` with `forest_hash.gdshaderinc` – the GLSL twin of `ForestFill`, same constants, uint32 arithmetic, fixed values tested – and the map textures bound once per map: the stand mask, parcels, lattice heights (RF); the shader knows no hexes; a cell without a tree collapses to a point; the base is the lattice height sunk 1.5 m more than the full trees; beyond 900 m from the camera every other cell is left out and the rest widen 1.4×, each tree at its own point of the band) to 1.4 km × h / 24 m (`VegetationRanges`). The picture (`tree_impostor_view.gdshaderinc`, shared with `tree_impostor.gdshader`, TreeField's per-instance impostors): one camera-facing quad per tree showing a baked picture of the real LOD0 model (a 16-view atlas rendered once at start through SubViewports, row per species x variant, the two views nearest the camera's direction relative to the tree's own yaw blended; a flat silhouette atlas where nothing renders). The impostors are lit by the scene (TASK-191): the bake renders every view twice with the unlit `foliage_bake.gdshader` (the LOD0 card shader under `IMPOSTOR_BAKE`) – unlit albedo and the encoded view-space normal, two atlases of one layout – and the impostor shaders turn the baked normal into the world with the bake camera's axes for the quad (tilted with the lattice slope by `impostor_slope_share` in the GPU-placed forest), so the sun, shadows and ambient light them as they light the full trees (`impostor_albedo` matches the tone). Beyond, `ForestShell` covers the map's forest tiles with a `canopy.gdshader` shell faded in by camera distance (`near_fade`), painted in the unlit atlas mean per species with dome normals standing on the drawn ground's normal (same slope share), lit by the same sun; over an impostor chunk not built yet the shell stays drawn at any distance (ForestField's coverage mask, one pixel per chunk). Burns reach the impostors as a uniform array; the field keeps the last 128 circles for full trees and impostors alike. The impostor sink and far thinning are `LookPreset.vegetation()` values (`impostor_sink_m`, `impostor_thin_from_m`, `impostor_thin_widen`). Under `true` the leaf colours are `LookPreset.REAL_SIZE_LEAF_COLORS` (summer greens, 1.5% autumn trees) and the cards carry many small leaves / short needle twigs (`LeafTexture.small_leaves` / `small_needles`). The full-tree budget (`full_tree_cap`) is a reach: full chunks nearest first while the count fits (`VegetationRanges.budget_reach`), the reach caps the LOD0 materials' `lod_cap` and the impostors' `full_reach`, so the farthest trees become impostors tree by tree. The first user is `ShrubField` (`RealScaleVegetation.shrubs`, built by `build_forest` after the forest, two layers on the camera-centred manager): `ShrubRules` (reference) / `shrub_rules.gdshaderinc` (twin) put at most one shrub per 2.5 m cell (`shrub_cell_m`) – none on keep-off, in water or inside a crop parcel (but on its 3 m edge strip and the balks: the raw `ParcelMap` texel and four neighbours at ±3 m), habitat by priority forest edge / clearing (blurred stand 8..246; ≥ 247 forest interior, none) > hedge > bank > heath > field edge > meadow, chance per habitat (~225 / ha edge, 1 per 2 m of hedge, ~140 / ha bank, ~80 / ha heath and ≤ 10 / ha meadow both modulated by a 50 m noise), four kinds by habitat mix (low bush 0.5–1 m on the undergrowth model, hazel / blackthorn 1.5–3 m and willow 2–3 m on the shrub model, juniper 0.8–1.5 m on the spruce model, heath only), heights in metres, colour per kind. `shrubs_near` (36 m chunks) draws the LOD0 model to `shrub_mesh_range_m` 60 m (`shrub_mesh.gdshader`: `foliage_body.gdshaderinc` under `PLACED_VEGETATION`, which takes the instance's variation, colour, origin and basis from `placed_instance()`; ## Ground marks (decals)

Tracks, craters and scorch (TASK-058) are cosmetic and view-only; no new event types. `GroundMarks` (pure, static) plans them: `track_segments(path_world, unit_class, unit_scale)` (tank = tread strips 0.42 wide, `mlrs` = tyre strips 0.34, infantry none; widths scale with `VisualScale.unit_model_scale() / 1.3`), `craters` / `impact_scorch` for indirect fire (attacker range >= 2, distance >= 2, not a counter), `death_scorch`, `reveal_fractions(points, path_time, rear_offset)` (share of each path segment's track mark that is drawn when the unit has walked `path_time`: from the start up to the unit's position minus `TRACK_REAR_OFFSET` 0.2, everything at the end) and `GroundMarks.Pool` (the `decals_max` cap: oldest track/tyre mark goes first, then craters, scorch last). Randomness is a hash of the view's own event serial, never `GameState.rng`. `DecalTextures` (static, cached) paints the albedo+alpha images. `GroundMarksView` (a node owned by `BattleController`) makes one `Decal` per mark; `BattleController` feeds it at the moment the matching animation plays (track marks are created at the start of the move, hidden, and grown by a tween with the same timing as `UnitView.move_along` – `GroundMarks.reveal_fractions` of `MoveAnimation.path_time` – so the visible end sits just behind the unit; the tween's last step reveals everything, so nothing stays half drawn; track decals have no fade-in; a decal evicted from the pool meanwhile is ignored; `GroundMarksView.add_growing_tracks` / `set_reveal`: the box never changes, the texture is swapped for a cached copy with the alpha cut at 1/32 steps of the length (`DecalTextures.revealed`), so the tread pattern never stretches; craters at the hit / last rocket impact, scorch when the death starts). Decals project onto visual layers 2 (terrain and backdrop, `MapView.TERRAIN_VISUAL_LAYER`) and 3 (grass chunks, so the blades are tinted rather than hiding the mark); units, trees, bushes and rocks stay on layer 1 and are never covered. Camera and light cull masks are the defaults. Decals are not verified on the Compatibility renderer (LOW on the WSLg build). `tools/screenshot.sh` shows them with `SCREENSHOT_MARKS=<unit id>` (demo marks around that unit, no animation).

## Units and factions

`UnitDefinition` (`src/core/data/`, one `data/units/<id>.tres` per real unit) holds `id`, `display_name` (real designation, or a translated descriptive name for squads), `short_name` (label, ≤ 6 characters), `unit_class` (`infantry` / `tank` / `mlrs`, ids from `docs/design/units/classes.json`), `mobility` (`foot` / `wheeled` / `tracked`, from the catalog) and the combat stats (`max_hp`, `move_points`, `attack`, `defense`, `effective_range_m`, `max_range_m`, `min_range_m`, `fire_mode`; hex values via `effective_hexes()` / `max_hexes()` / `min_hexes()`), derived by GDD "Stat derivation rules". Core rules read only the combat stats; `unit_class` and `mobility` group shared behaviour (presentation: volleys, locomotion, model contract – TASK-039b). `test_unit_catalog_consistency.gd` checks every unit against its catalog entry (`real_name`, `class`, `mobility`, roster factions ⊆ `operators`).

`FactionDefinition` (`src/core/data/`, instances in `data/factions/*.tres`) holds a faction's `id`, `display_name` (translation key), `short_name`, `roster: Array[UnitDefinition]`, `default_force: Array[UnitDefinition]` (the default battle's units in spawn order, each in the roster) and a Presentation group (`color`, `ink_color`, `camo`, `vest_color`) that core/AI never read. `FactionRegistry.get_faction(id)` / `all()` / `ids()` / `has_faction(id)` look them up (explicit path table, see ADR 0007). Each player has a faction id in `GameState.player_factions` (default `FactionRegistry.DEFAULT_IDS` = `poland`, `russia`); the view gets everything faction-specific from `state.faction_of(player_id)` – never from owner-indexed constants. `Scenario.default_battle(seed, factions)` assigns them and spawns each player's `default_force` in list order: range-1 units fill the front slots, the others the back slots (`Scenario.FRONT_SLOTS` / `BACK_SLOTS`; a force larger than the slots → `push_error`, extra units skipped). The map doesn't depend on the factions (spawn tiles are forced to plains); unit ids follow the spawn order, so they depend on the forces. Units outside the owner's roster are skipped. Balance between factions comes from `default_force` (unit counts), never from unit stats; `MatchRunner.play(seed, max_turns, factions)` / `tools/simulate.sh --factions=<p0>,<p1>` measure it.

## Two layers

The game is growing an operational layer (formations, supply, deep strikes) above the tactical battle; the shape is fixed in [ADR 0015](adr/0015-two-layer-architecture.md):

- Operational logic goes to `src/core/operational/` and `src/ai/operational/` with the same rules as `src/core/` (pure logic, commands, its own `rng`); `OperationalState` / `OperationalSimulation` / `OperationalCommand` mirror the tactical classes but are separate. The operational layer never touches `GameState`; the tactical layer knows nothing about the operation.
- `src/core/operational/` (TASK-092b): `OperationalState` (operation id, `grid`, `player_sides`, `player_factions`, `first_player` / `current_player`, `turn`, `formations` in placement order, `rng`, `pending_battles`; `get_formation`, `formation_at`, `snapshot()`), `OperationalSimulation` (`execute(command)` – validate → `command_rejected` or `history` + `event_emitted`), `OperationalCommand` (base) and `OperationalCommandCodec` (strict `from_dict`, same number rules as `CommandCodec`), `Formation` (runtime: `id`, `owner_id`, `definition`, `coord`, `companies: Array[Formation.Company]` with `unit_type`, `strength`, `max_strength`, `ref` = `"<formation id>/<n>"`) and `Operation` (`NAMES`, `build(id, seed)`, `from_definition(definition, seed, grid = null)` – validates sides, factions, rosters and placements, null with `push_error`). The human's side is not part of the state (it lives in the session), so an operation replays identically for either choice.
- Operational data (`src/core/data/`): `FormationDefinition` (`data/formations/<id>.tres` – faction, echelon, `formation_class`, `move_points`, ordered `companies`), `SideDefinition` (`data/sides/<id>.tres` – a player's bloc: `lead_faction`, `factions`; `find(id)`), `OperationDefinition` (`data/operations/<id>.tres` – `map_id`, `sides` by player, `first_player`, `formations: Array[FormationPlacement]`) and `FormationPlacement` (id, display name, `parent` label, player, type, axial `coord`).
- Operational movement (TASK-092c, pure functions, nothing changes state): `OperationalMovement` (`src/core/data/operational_movement.gd`, `data/operational/movement.tres`: `move_costs` by `Terrain.Type` with 0 = impassable, `road_cost`, `river_extra_cost`, `shipped()`, `problem()`, `step_cost(grid, from, to)` – road link 1, else terrain cost + river extra, water / off-map `Terrain.IMPASSABLE`). `OperationalRoutes` (`src/core/operational/operational_routes.gd`): `plan(state, formation, destination, avoid_contact)` – cheapest route without a point limit (enemy hexes impassable, own formations passable but never the destination; with `avoid_contact` the zone of control – hexes next to an enemy – is impassable except the destination; bucket-queue Dijkstra, ties follow `Hex.DIRECTIONS` order), `walk(state, formation, from, route, budget)` → `{steps, end, cost, stop}` (the first step is always taken, unused points are lost, never ends on another formation, `stop` = `arrived` / `contact` (entered a zone-of-control hex that is not the last) / `out_of_points`) and `forecast(state, formation, destination, budget, avoid_contact)` – the end hex of every turn (ends on arrival, contact, no movement or after 99 turns).
- Formation orders (TASK-092d; executed by `EndOperationalTurnCommand`, TASK-092e): `OperationalPosture` (`src/core/data/operational_posture.gd`, `data/operational/postures/<id>.tres`: `id`, `display_name`, `move_percent`, `avoids_contact`; `NAMES` = march / advance / defend, `find(id)`, `problem()`, `budget(move_points)` = `move_points * move_percent / 100` rounded down, at least 1), `OperationDefinition.initial_posture`, `Formation.posture` / `Formation.order` (`FormationOrder`, `destination`; null = no order; both in the snapshot) and the commands `IssueOrderCommand(formation_id, destination, posture)`, `CancelOrderCommand(formation_id)`, `SetPostureCommand(formation_id, posture)` (shared checks in `OperationalOrders`; codec types `issue_order`, `cancel_order`, `set_posture`). Orders per turn (human decision 2026-11-13): `IssueOrderCommand` is rejected with `no_orders_left` once `OperationalState.orders_issued` reaches `orders_per_turn(player)` (`BattleConditionsRules.orders_per_turn`, C2 integrity, `orders_base` / `orders_floor` in `data/battle/conditions.tres`); the count resets in `EndOperationalTurnCommand` and enters the snapshot only when above 0; the operational AI plans within `orders_left()`. Cancel order and set posture are free. A contact battle's `Conditions.command_points` stays 0 (unlimited).
- Order execution (TASK-092e): inside `EndOperationalTurnCommand.apply`, before `operational_turn_ended`, each formation of the **current player** with an order (in `state.formations` order, each seeing the earlier ones' new positions) is handled in this order: destination holds a formation -> `formation_order_interrupted` (`destination_occupied`); `OperationalRoutes.plan` (posture's `avoids_contact`) empty -> `no_route`; `walk` with `posture.budget(move_points)` that moves nothing and stops `out_of_points` -> `blocked`; otherwise the formation moves (`formation_moved`, always first) and `arrived` -> order removed + `formation_order_completed`, `contact` -> `formation_halted` and the order is kept, `out_of_points` -> still en route. Posture is never changed; execution draws nothing from `state.rng`; validation is unchanged (`battle_pending` only).
- Borders in movement and battle (TASK-116): `OperationalRoutes.plan` treats every hex of a country with `CountryRules.may_enter_country == false` as impassable (the destination too), except the country the formation stands in (`closed_countries`, `destination_closed`) – a formation is never trapped; `walk` / `forecast` follow the plan, zones of control are unchanged. `IssueOrderCommand` rejects such a destination with `closed_country` (after `invalid_destination`, before `occupied`); order execution checks it first and interrupts with `closed_country` (before `destination_occupied`). Incidents inside the execution step: right after a formation's `formation_moved`, `EscalationRules.on_steps` goes through the entered hexes in order – `breach` (`sanctuary_breached`, `escalation_changed`, ...) and the casus belli of a step out of an **aligned** country into an enemy one (`casus_belli_gained`, once per country and player); incidents never end the operation (TASK-140). `EscalationRules.route_incidents(state, formation, route)` is the pure forecast: `{type: &"sanctuary_breach", country, at, steps, ends_operation}` (`steps` clipped to the cap, 0 at the cap; `ends_operation` always false since TASK-140) / `{type: &"casus_belli", country, for_player, at}`. `ContactRules.battle_allowed` also requires `CountryRules.may_enter(attacker.owner_id, defender.coord)`; a halted formation that only the border keeps from fighting gets `contact_forbidden`. `BattleConsequences.retreat_hex` never picks a hex closed to the retreating player (none left -> the existing no-retreat rule). Battles never touch the escalation level or the casus belli flags.
- Battle consequences (TASK-095): `ResolveBattleCommand.apply` pops the setup, emits `battle_resolved` and calls `BattleConsequences.apply(state, setup, result)` (`src/core/operational/battle_consequences.gd`, static, no `rng`, reads only the companies' `strength_end`, `field_holder` and `retreat` – never `resolution`, so played and auto results with equal fields give equal states): each `Formation.Company` (matched by `ref`) gets `strength_end`, a company at 0 is removed, a formation without companies is removed (`formation_destroyed`, cause `battle`); `retreat` (player) makes that player's formation fall back one hex to the passable, free neighbour outside enemy zones of control when one exists, else any, farthest from the enemy (ties in `Hex.DIRECTIONS` order; `BattleConsequences.retreat_hex`), dropping its order (`formation_order_interrupted`, `retreated`), event `formation_retreated` (`blocked` true and no move when no hex is free); the field holder does not advance. `Formation.readiness` (0 … 100, start 100) and `Formation.fought` are in the snapshot; participants lose `readiness_loss_attacker` 15 / `readiness_loss_defender` 10 (`AftermathSettings`, `src/core/data/aftermath_settings.gd`, `data/operational/aftermath.tres`: also `readiness_recovery` 10, `readiness_floor` 40; `shipped()`, `problem()`); `EndOperationalTurnCommand` calls `BattleConsequences.recover_readiness` after switching sides: the new current player's formations that did not fight since their last turn began regain the recovery (cap 100), then `fought` is cleared. Per battle a `BattleSetup` is appended to `pending_battles` (FIFO) and **one `state.rng.randi()` draw** gives its `seed`. - Countries and stances (TASK-114, ADR 0020, GDD "Countries and stances"): `CountryDefinition` (`src/core/data/country_definition.gd`, `data/countries/<id>.tres`: `id`, `iso_code`, `display_name`, `sanctuary`; `NAMES`, `find(id)`, `find_by_iso(code)`), `CountrySetup` (sub-resource of `OperationDefinition.countries`: `country`, `stance`, `side`, `leaning`, `contribution: Array[FormationPlacement]`), `CountryState` (runtime: `id`, `definition`, `stance` neutral / aligned / belligerent, `side`, `leaning`, per-player `casus_belli`, `breached_by`, `declared_by`, `contribution`, `contributed`; `snapshot()` has `contributed`), `OperationalState.countries` / `get_country(id)` / `country_at(coord)` (`Operation.build` maps the map's ISO codes via `ImportedMap.country_at`; `from_definition(..., grid, country_map)` takes a `Vector2i -> StringName` map for hand-made grids; it rejects invalid stances, duplicate / unset countries and formations starting on a closed hex) and `CountryRules` (static, `src/core/operational/country_rules.gd`: `relation(state, player, country_id)` -> own / enemy / hostile / neutral / none, `may_enter`, `may_strike`, `transition_problem`, and `set_stance(state, country_id, stance, side, cause, by)` – the **single** place a stance changes; relations are computed, never stored).

JSON `{"version": 1, "operation", "seed", "human_side", "commands", "battles": [{setup, commands, result, resolution}]}`; strict `from_dict` / `from_json` (null on a missing / malformed field, another version, an undecodable operational or tactical command; commands are kept in canonical `to_dict()` form). `from_simulation(simulation, seed, side, battles)`. `replay(full := false)` = `Operation.build(id, seed)` + `replay_on(state, full)`: every command through `OperationalSimulation.execute`, each `ResolveBattleCommand` takes its entry's result (they must be equal, else `invalid_record`) → `{ok, simulation, events}` or `{ok: false, error, index, battle, reason}` with `unknown_operation` / `invalid_side` / `invalid_command` / `diverged` (rejected command, or in full mode `reason` `battle_setup`: `ContactBattle.prepare` at that point differs from the stored setup) / `invalid_record` (resolve commands and entries do not pair up) / **`battle_diverged`** (full mode: `BattleReplay.problem` – `src/core/battle_replay.gd`, the tactical half, so `src/core/operational/` still never names `GameSimulation` / `Command` – finds that `Scenario.from_setup(entry.setup)` + its tactical commands give another `BattleResult`, a rejected command or no end). `battle_diverged` is a replay error code, not an event. A pending battle has no entry (a battle in progress is never recorded); replaying the commands puts it back into `pending_battles` with the same setup and seed. `Session` keeps the campaign seed and the played battles (`start_campaign(simulation, id, seed)` when a staff map builds a new operation, `finish_battle(battle_simulation)` appends the entry, `record(viewer)` – null during a battle, `resume(record, simulation)` + `resuming()` for Continue). Files: `CampaignSaver` (`src/presentation/campaign_saver.gd`) writes `user://campaigns/<operation id>.json` atomically (`<path>.tmp`, then rename), `latest(dir)` = the newest save, `load_campaign(path)` → `{record, simulation, error, detail}` with `error` `unreadable` / `corrupt` / `replay_failed` (fast replay), never a crash. Staff map: `F5` / Save button → `save_campaign()` with a "Saved" toast; main menu: Continue (disabled with "No saved campaign yet") loads the latest save, `Session.resume` and opens the staff map, which takes the operation id and seed from `Session`, the replayed simulation and the saved side as viewer, and rebuilds the contact queue from `pending_battles`.

## Replays and match records

A match is fully described by `scenario + seed + executed commands` (state is never serialized).

- `Command.to_dict()` gives a JSON-compatible form (`{"type": "move", "unit_id", "target": [q, r]}`, `{"type": "attack", "attacker_id", "target_id"}`, `{"type": "end_turn"}`); `CommandCodec.from_dict(d)` (`src/core/commands/command_codec.gd`) rebuilds it and returns `null` on anything unknown or malformed. JSON parses every number as a float: integral floats become `int`, non-integral / non-finite / beyond ±2^53 values, bools and strings are rejected. A new command type = `to_dict()` + a branch in `CommandCodec` + a codec test.
- `MatchRecord` (`src/core/match_record.gd`): `version` (2), `scenario`, `seed`, `factions: Array[StringName]` (required), `commands: Array[Dictionary]`; `from_simulation(sim, seed, scenario = "default_battle")` copies `sim.history` and `sim.state.player_factions`, `to_json()` / `from_json(text)` (`null` on invalid JSON, version ≠ 2 or malformed fields; extra keys ignored). `parse_json(text)` returns `{"record", "error"}` with a readable message instead – e.g. version 1 records (before TASK-039a's real units) are reported as unsupported (ADR 0009). `MatchRecord.normalize(value)` turns integral floats of parsed JSON back into ints for comparisons.
- `Replay.run(record)` (`src/core/replay.gd`) builds the scenario's state from the seed (`Scenario.build(name, seed, record.factions)`; `Scenario.NAMES` = `"default_battle"`, `"objective_battle"`, `"command_points_battle"`, `"suwalki_battle"` – the real-terrain sample on `data/maps/suwalki.tres`) and executes each decoded command through `GameSimulation.execute`. Errors: `unknown_scenario` (index -1), `invalid_factions` (unknown id or not two ids; index -1), `invalid_command` (codec returned `null`), `diverged` (rejected; `reason` = the `validate()` code).
- `GameState.snapshot()` is the comparable state description (turn, current player, winner, `end_reason`, `rng_state`, `objectives` = `[[q, r, owner], ...]` sorted by (q, r) – `[]` without objective hexes –, `command_points`, units sorted by id incl. dead, each with `activated`). Command points (TASK-091): `GameState.command_points_per_turn` (N per player, 0 = unlimited; from `BattleSetup.conditions[i].command_points` in `Scenario.from_setup`) is static match data; `command_points` (the current player's remaining points) and `Unit.activated` are state. A unit's first move or attack of a turn costs 1 point (`GameState.activate`), later actions are free, counterattacks never activate; without points left a not-yet-activated unit is rejected with `no_command_points` (`GameState.can_activate`, `is_command_limited(player)`). Static match data (`objectives`, `starting_hp`, `command_points_per_turn`, factions) is rebuilt by the scenario and not in the snapshot. `rng_state` is stored as a **String** because the 64-bit RNG state does not survive a JSON double.
- Combat rolls (TASK-089a) are the only consumer of `GameState.rng` during a battle: `AttackCommand.apply()` calls `rng.randi_range(1, striker max_hp)` exactly `striker.hp` times for the strike (all shots, even once the target is dead), then – only if the counter happens – `defender.hp` (after the hit) times for the counter. `validate()`, `AttackCommand.forecast()` / `CombatForecast` (exact binomial odds for the HUD and the AI) and the AI's decisions never touch the rng, so replays (which store commands only) stay deterministic.
- Regression fixture `tests/fixtures/replays/default_battle_12345.json` (AI vs AI, seed 12345, until `game_over` or turn 30) = record + `"expected_final"` snapshot; `test_replay.gd` replays it. After an *intended* rule change, regenerate it with `tools/make_replay_fixture.sh` (headless `tools/make_replay_fixture.gd`) and commit the new file.

## Coordinates

Hex grid, axial coordinates `(q, r)` as `Vector2i`, "pointy-top" layout. World ↔ tile conversions in `Hex.to_world` / `Hex.from_world`. Rectangular maps are generated in offset layout (`MapGenerator.offset_to_axial`).

Maps from real geography (TASK-087, [ADR 0018](adr/0018-maps-from-real-geography.md)): `tools/import_map.py` (offline, from a download cache outside git) writes `data/maps/<id>.tres` (`ImportedMap`, `src/core/data/imported_map.gd`) – same offset layout, row 0 north, one terrain character per tile, game elevation and the real DEM metres per tile, the dominant cover class per tile, and road / river link masks per tile (TASK-108, [ADR 0019](adr/0019-roads-rivers-real-terrain-types.md)). Tactical scale: 250 m between neighbouring hex centres, so one world unit = 250 / √3 ≈ 144.3 m. Geo-reference: UTM of the theatre (`crs`, 34N for the Suwałki Gap), tile (0, 0) centre at (`origin_easting`, `origin_northing`), world x east, world z south (`ImportedMap.easting` / `northing` / `projected_to_tile`). `ImportedMap.find(id).to_grid()` gives a `HexGrid` with `authored_elevation` (no `field`); `BattleSetup.map_id` = an imported map id loads it in `Scenario.from_setup`. Sources and attribution: `data/maps/CREDITS`. Operational maps also carry **graphic layers** for drawing only (TASK-126): `water` / `cover` (250 m) and `relief` (500 m hillshade) PNGs in `ImportedMap.layer_*_png`, decoded with `layer_image(kind)` / `layer_bytes(kind)`, placed with `layer_world_rect(kind)`; `has_graphic_layers()` is false on tactical and older maps; no rule reads them (ADR 0018 "Graphic layers").

**Land cover** (TASK-108g, [ADR 0028](adr/0028-sub-hex-land-cover.md) "Sub-hex land cover; hexes are mechanics only"): tactical maps and the tactical layer carry a **land-cover raster** – one `LandCover.Kind` byte per 16 m cell (`OPEN, GRASS, FIELD, URBAN, FOREST, MARSH, WATER` = the importer's cover classes, plus `ORCHARD, SCRUB, BARE`, whose rule class is `LandCover.PARENT`: field, grass, grass), row 0 north. `ImportedMap.land_cover` (zlib, `land_cover_cell_m` / `_width` / `_height` / `_origin_easting` / `_origin_northing` = centre of the north-west cell); in the layer the same geometry in `layer.tres` and one non-overlapping window per chunk (`TacticalChunk.cover`, `cover_column` / `cover_row` / `cover_width` / `cover_height`, decoded only on demand). The importer derives each hex's `Terrain.Type` from the cells inside it (`classify` on their counts), so data flows one way: raster → look, raster → per-hex type → rules. **`LandCover`** (`src/core/data/land_cover.gd`, pure, read-only, no RNG) is its reader for the view: `LandCover.for_map(map_id, map_region, grid, margin)` (the layer cut `TacticalLayer.region_land_cover(region, margin)` in the cut's world frame, or `LandCover.from_imported(map)`, else `LandCover.from_grid(grid)`), `class_at(x, z)`, `share_in(rect, kind)` / `shares_in(rect)`, `weight(kind, x, z)` / `weights_at(x, z)` (bilinear between cell centres, continuous across hex borders), `cells()` / `width` / `height` / `origin` (centre of cell (0, 0)) / `cell_size` (world units) / `world_rect()` for a texture. `has_raster()` is false for the fallback of generated / older maps, which expands the hex types (`kind_of_terrain`, hard hex edges) so those maps keep their look. No rule reads the land cover.

**Satellite colour** (TASK-192a, [ADR 0031](adr/0031-satellite-colour-layer.md)): tactical maps and the tactical layer imported with `tools/import_map.py --colour` carry an sRGB colour raster from a Sentinel-2 L2A summer composite (10 m on tactical maps, 40 m in the layer), stored as baseline JPEG: `ImportedMap.colour_jpg` (+ `colour_cell_m` / `_width` / `_height` / `_origin_easting` / `_origin_northing` = centre of the north-west pixel, `colour_sources`); in the layer the geometry in `layer.tres` and one JPEG window per chunk (`TacticalChunk.colour_*`, each one pixel wider east / south than its share, decoded on first sample). `ColourRaster` (`src/core/data/colour_raster.gd`, pure) holds a decoded window (`sample(x, z)`: bilinear between pixel centres, clamped to the edge). `ImportedMap.has_colour_layer()` / `colour_raster()` / `sample(x_m, z_m)` and `TacticalLayer.has_colour_layer()` / `sample(x_m, z_m)` take metres east / south of tile (0, 0)'s centre and return transparent black without a layer. Only the view reads it (TASK-192b); no rule does.

Terrain types and movement (TASK-108, [ADR 0019](adr/0019-roads-rivers-real-terrain-types.md)): `Terrain.Type` = `PLAINS, FOREST, HILLS, WATER, FIELDS, URBAN, MARSH` (new values appended; `data/terrain/<id>.tres`); the last three come only from imported maps (`MapGenerator` never makes them). Roads and rivers are stored per tile as **6-bit link masks** (`HexGrid.road_links` / `river_links`, bit *i* = a link towards `c + Hex.DIRECTIONS[i]`; `ImportedMap.road_rows` / `river_rows`, one `ImportedMap.LINK_CHARS[mask]` character per tile, empty = none; a land–land link is stored on both tiles, land → water / off-map only on the land tile, water has none – `ImportedMap.problem()` checks it). **`HexGrid.step_cost(from, to)`** is the one movement cost every search uses (`reachable`, `path_to` → `MoveUnitCommand`, the AI, path preview and the terrain panel path cost): `IMPASSABLE` off the map / impassable; `road_move_cost` when `from` has a road link towards `to`; else `move_cost(to)` (+ `river_extra_cost` when `to` is a river hex = any river link). Numbers: `TerrainFeatures` (`src/core/data/terrain_features.gd`, `data/terrain/features.tres`, `Terrain.features()`). `move_cost(c)` stays the bare terrain cost (terrain panel). `Scenario._deployment_tiles` (imported maps) picks free plains or fields tiles.

| `strike_launched` | `player`, `means`, `count`, `target` (id), `coord` (Vector2i), `class_id` (`airfield`, `depot`, `c2`, `air_defence`, `formation`), `launcher_kind` (String, TASK-147: `fighter`, `bomber`, `ship`, `submarine`, `launcher`, `drone_site`), `origin` (Vector2i, launch hex from `StrikeRules.launch_origin`, no rng draw; older events lack both) | StrikeCommand |
| `strike_resolved` | `player`, `means`, `target`, `count`, `intercepted`, `hits`, `misses`, `p_intercept`, `interceptor_ids` (`Array[StringName]`: the sites counted, setup order, TASK-098a), `p_hit`, `damage_dealt`, `target_destroyed` | `StrikeRules.resolve` (via StrikeCommand) |
| `installation_changed` | `id`, `before`, `after`, `destroyed`, `cause` (`strike`, `repair`) | `StrikeRules.resolve`, `StrikeRules.end_round` |
| `installation_suppressed` | `id`, `before`, `after` (`suppressed_rounds`), `cause` (`strike`, `lapse`) | `StrikeRules.resolve` (after `installation_changed`, every hit on a surviving air-defence site), `StrikeRules.end_round` (countdown) |
| `formation_damaged` | `formation_id`, `player`, `at`, `before`, `after` (total strength), `cause` (`strike`) | `StrikeRules.resolve` |
| `formation_destroyed` | `formation_id`, `player`, `at`, `before`, `after` (0), `cause` (`strike`); the formation is removed from the state | `StrikeRules.resolve` |

`OperationalClock` (pure) maps a turn to its date (from `OperationDefinition.start_date`, 12 h per turn) and day / night (odd turns 06:00–18:00).

**Operational journal** (TASK-148a; no new event types): `OperationalState.journal` (`OperationalJournal`, pure, no RNG) keeps one `Entry` per journal-worthy event (`turn`, `category` strike / battle / move / politics, `kind`, `actor`, `involved`, optional `coord`, plain `args`). `OperationalSimulation.execute` feeds every event of an accepted command to `journal.on_event` (next to `PoliticalLog`); the state it sees is the state after the whole command, so sides come from event fields or the surviving formation. `entries_for(player)` returns the entries whose `involved` is empty (both sides) or holds the player: own actions in full, the enemy's only where it touched the side (strikes, battles, a halt next to an own formation). A strike is one entry (`strike_launched` + `strike_resolved` + its `installation_changed` / `formation_damaged` / `formation_destroyed` effects folded into `args`). Political entries never store who decided. No cap; `snapshot()["journal"]`; a dict without it loads empty.

**Journal view** (TASK-148b): `StaffMapJournalWindow` (a `StaffMapWindow`, left dock, bottom bar JRN / key J) reads only `state.journal.entries_for(viewer)`; the pure `StaffMapJournalText` turns `(entry, viewer, state)` into the viewer's sentence, tag, side shape, place line and turn header (dates from `OperationalClock`). The owner (`StaffMap`) rebuilds the open window once per frame after events (a dirty flag), `StaffMapStrikeReports` emits `log_requested(model)` (Enter / click) and the owner opens the journal at that strike entry; a click on an entry centres the map and shows `StaffMapJournalRing` for 2 s.

## Localization

All UI strings live in `assets/i18n/strings.csv` (columns `keys,en,pl`); Godot imports it into `strings.<locale>.translation`, registered in `project.godot` (fallback `en`). Keys are the English source strings (gettext style): `tr("Your turn")`, format strings are keys too and values are substituted after translation: `tr("Turn %d") % turn`. Static/pure helpers without `Object.tr()` call `TranslationServer.translate(key)`. Labels whose text is composed in code set `auto_translate_mode = Node.AUTO_TRANSLATE_MODE_DISABLED` so the text is not translated twice. Every new UI string = a CSV row with `en` + `pl` (`tests/unit/test_localization.gd` checks coverage and placeholders). To try Polish, set the project setting `internationalization/locale/test="pl"` (do not commit it).
