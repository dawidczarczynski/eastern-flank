# Architecture

## Layers

```
┌──────────────────────────────────────────────┐
│ Presentation  (Node, scenes, input, UI)      │  src/presentation/, scenes/
│  BattleController · MapView · UnitView · …   │
└───────────▲───────────────────────┬──────────┘
            │ events (Dictionary)    │ commands (Command)
┌───────────┴───────────────────────▼──────────┐
│ GameSimulation  – validate → apply → emit    │  src/core/game_simulation.gd
├──────────────────────────────────────────────┤
│ GameState · HexGrid · Unit · Terrain         │  src/core/
│ Commands                                     │  src/core/commands/
│ Scenario (headless battle setup from a seed) │  src/core/scenario.gd
│ AiPlayer (issues commands like a player)     │  src/ai/
├──────────────────────────────────────────────┤
│ Data: UnitDefinition, FactionDefinition, …   │  src/core/data/, data/
└──────────────────────────────────────────────┘
```

Dependencies point downward only. `src/core` doesn't know graphics exist.

## Flow of a single action

1. The player clicks a tile → `BattleController` creates `MoveUnitCommand(unit_id, coord)` (or `AttackCommand(attacker_id, target_id)` when the tile holds an enemy).
2. `GameSimulation.execute()` calls `validate()`. A rejected command → `command_rejected` signal with a reason code (e.g. `unreachable`, `out_of_range`, `already_attacked`). Once `GameState.winner != -1` every command is rejected with `game_over`.
3. `apply()` changes `GameState` and returns events; the simulation emits them via `event_emitted`.
4. `BattleController` turns events into animations (`UnitView.move_to`) and refreshes the HUD.

The AI (`AiPlayer.take_turn`) does exactly the same, just without clicks.

## Unit visuals

`UnitView` = model (`UnitModels.build`: a registry that loads `src/presentation/models/<unit_id>.gd`, built with `ModelParts` primitives and shared meshes/materials, faces +X; each unit model is built once per unit and faction, units get copies with their own node trees and the camo materials and the per-unit `wear_seed` restored per copy; `UnitModels.build` takes the unit id for the seed) + faction marker draped on the terrain (`OverlayGeometry`) + HUD `UnitLabel` (a `Control` projected via `Camera3D.unproject_position`, anchored at the model file's `LABEL_HEIGHT` through `UnitModels.label_height`). The "done" dimming uses the pure helper `UnitStatus.is_done`; `BattleController` pushes selected/hovered/done state into the views.

Mechanisms (TASK-043, ADR 0014): what a unit animates is declared per unit in its catalog entry (`mechanisms`, registry `docs/design/units/mechanisms.json`). The model file copies it into a `MECHANISMS` constant and stores it on the built model with `ModelParts.declare_mechanisms` (node metadata `mechanisms`, which survives `ModelParts.cached` copies); `UnitModels.mechanisms / mechanism(model, id) / has_mechanism` read it, so no `src/presentation` code touches `docs/`. Pivots activate a mechanism, the metadata parameterises it. `tests/unit/test_unit_mechanisms.gd` (helper `tests/mechanism_contract.gd`, test-only read of the catalog and registry) fails when a model's metadata differs from its catalog entry, when an implemented mechanism's pivots are missing, or when a model owns the pivot of a mechanism it doesn't declare.

Main menu and unit catalog (TASK-084): the game starts in `scenes/ui/main_menu.tscn` (`run/main_scene`; `MainMenu`: Start operation loads `scenes/battle/battle.tscn`, Language cycles `GameSettings.LOCALES` through `GameSettings.set_locale`, stored in `user://settings.cfg` and applied at start by `GameSettings.apply_saved`, Unit catalog loads `scenes/ui/unit_catalog.tscn`; widgets in code via `MenuStyle`). The catalog (`src/presentation/catalog/`, UI in `src/presentation/ui/unit_catalog.gd`) holds no `GameState`: `CatalogUnits` lists `data/units/*.tres` (path table, test-checked against the folder) grouped by class, `CatalogStage` shows one stand-alone `UnitView` (built by `UnitModels.build`, the battle's path) on a ground disc under the battle's sun and environment, `CatalogAnimations.for_model` maps the model's declared mechanisms to animation buttons (a table `mechanism id -> animation ids`; a new mechanism = a row plus a handler in `CatalogStage`), and `OrbitMath` (pure) holds the orbit camera maths. The deploy / raise / traverse / salvo / stow tween steps are `VolleyPlayback`, used by `BattleController._play_volley` and the catalog alike. `tools/screenshot.sh` renders the menu and catalog (`SCREENSHOT_SCENE`, `SCREENSHOT_CATALOG`, see tools/screenshot.gd).

Rocket salvo (TASK-074): `RocketVolley` plays the salvo as a pure function of the salvo time (`update(t)`, driven by one `tween_method`, so the speed scale applies): one rocket per `Mouth*` tube (`UnitView.launch_points` / `launch_directions`, the pod's +X; fallback above the unit, 45° up), launched `SalvoTiming.interval` apart, each on a cubic Bézier (`RocketVolley.path_point`) that leaves along its tube and comes down steeply on a landing point inside the target tile (`SalvoTiming.landing_points`, a view-local RNG seeded from the event serial and the attacker, never `GameState.rng`). Launches and impacts in `(previous t, t]` come from the pure `SalvoTiming.crossings`, so none is skipped or repeated; each fires the signals `rocket_launched(index)` / `rocket_impacted(index, point)` and the effect hooks of `SalvoEffects` (`begin`, `on_launch`, `on_flight` with contiguous segments, `on_impact`, `end`; no-ops in the base class, assigned by `BattleController._play_volley`; TASK-075 fills them). The simple look is a small rocket mesh with a tail glow while the motor burns, launch and impact flashes (`FlashFx`, an additive expanding ball, mesh only, shared with later effects) and a pod jolt per launch (`UnitView.set_launcher_jolt`); no particles, no lights. `VolleyPlayback.connect_hp_steps` steps the target's shown HP (`UnitView.set_shown_hp`) down with every impact (`SalvoTiming.hp_after_impact`, exactly the event's `target_hp` at the last one), plays the hit reaction on the first and the last impact and adds the ground marks at the first.

Mesh kit (TASK-030, ADR 0012): `MeshKit` (`models/parts/mesh_kit.gd`, pure geometry, one material) builds chamfered and smooth primitives – `cbox`, `pillow`, `lathe`, `rod`, `bolt`, `stack`, `loft`, `plate`, `profile`, `sweep`, `tube` – in the caller's units (metres), optionally mapped by a `VehicleFrame` and a pivot `base`; `MeshKits` keeps one kit per material role (`k(&"body")`) and `add_to(pivot, materials)` adds one `MeshInstance3D` per material via `ModelParts.add` (pivots that move get their own `MeshKits`). Front faces are clockwise seen from outside (`(v2 − v0) × (v1 − v0)` along the normals). Every primitive writes the **vertex masks** in `ARRAY_COLOR` (8-bit), the contract with the paint shader:

| Channel | Meaning | Written as | Paint use |
|---|---|---|---|
| `r` | chamfer / edge | 1 on chamfer bands, box corners, plate rims, short diagonal lathe segments (< `chamfer_max`), tube end caps; 0 on faces | paint wear |
| `g` | openness | the kit's `openness` (1 = open, set lower by the model for recessed parts), × `INNER_OPENNESS` (0.35) on a lathe's inner wall | cavity darkening |
| `b` | per-part tint seed | `MeshKit.tint_seed(part centre)` – hash, constant per primitive call, deterministic | per-part tint |

## Graphics quality

`GraphicsQuality` (`src/presentation/graphics_quality.gd`, pure static) picks the LOW/HIGH preset (`detect` from renderer + adapter, `--quality=` override via `parse_override`) and holds the feature switches (`features`); `BattleController` applies them to the environment/sun/viewport (shadows, MSAA, 3D render scale) and passes `quality` to `MapView` (LOW: no foliage scatter) / `UnitView`.

`ColorGrade` (`src/presentation/color_grade.gd`, pure static, TASK-051) is the muted/olive colour grade: `grade(c, params)` and `lut(size, params)` bake a 3D LUT (`cached_texture()`, built once); `GraphicsQuality.apply_environment` assigns it as `adjustment_color_correction` on HIGH (feature `color_grade`) and disables adjustments on LOW.

HUD v3 building blocks (TASK-076, ADR 0013, `src/presentation/ui/`): `UiPalette` (tokens), `HudTheme` (`display(weight)` Chakra Petch, `mono(weight)` JetBrains Mono), `HudShapes` (pure chamfer / hex / tab / hatch / ruler geometry), `FramedPanel` (chamfered 1 px frame + header tab + brackets, a `MarginContainer`), `HatchBar`, `Bracketed`, and `ScreenDecor` (vignette + scanlines + corner brackets in one shader, first child of the HUD root).

## Terrain rendering

`MapView` builds one continuous terrain mesh (heights from `TerrainSurface`, 4 vertices per world unit) plus the backdrop ring (`BackdropMesh`, TASK-052; the map terrain it copies along the border comes from `BackdropTypes`, cached per border vertex), both drawn with one `ShaderMaterial` on `assets/shaders/terrain.gdshader` (`TerrainGround.material`, TASK-055):

- **Layers**: six CC0 ground materials (`assets/third_party/textures/ground/<layer>/`, credited in `credits.json`) in a fixed order: `0 grass`, `1 dry_grass`, `2 dirt` (also forest floor), `3 mud`, `4 gravel`, `5 rock`. `TerrainTextures` (static) decodes and packs them on the `WorkerThreadPool` while the mesh is built into three `Texture2DArray`s – `albedo_height` (RGB albedo, height in A), `normal_maps` (OpenGL), `roughness_ao` (R roughness, G AO) – size from `GraphicsQuality.features` `terrain_texture_size` (HIGH 1024², LOW 512²), cached per size.
- **Weights**: `TerrainSplat.weights(terrain, slope, height, water_level, moisture, macro)` (pure, static, `tests/unit/test_terrain_splat.gd`) gives six weights summing to 1 per vertex (plains: grass/dry grass by macro noise + dirt patches; forest: dirt floor; rock/gravel by slope and on high ground; mud/dirt shore band 0.12 above the water; water beds mud), then `TerrainSplat.smooth` averages neighbours within one mesh step. Layers 0–3 are stored in `ARRAY_COLOR` (8-bit, quantised so the sum stays within ±0.01), 4–5 in `ARRAY_CUSTOM0` (RGBA float, `TerrainGround.add_surface`; `.zw` free for TASK-035 roads/fields). `ARRAY_TEX_UV2` carries a value/saturation factor (darkened off-map margin, muted backdrop).
- **Shader**: world-space sampling at `layer_repeat` (real-world size / 7.7 m per unit × `TerrainGround.REPEAT_SCALE`), height blending (`w + h − max + 0.2`), roughness remapped to `[roughness_min, 1]`, AO, ±8 % low-frequency macro brightness, darker lake beds by depth. Uniforms `anti_tiling` (second sample ×3.7, rotated 37°, mixed by noise) and `triplanar` (rock on steep slopes) come from `GraphicsQuality.features` (`terrain_anti_tiling`, `terrain_triplanar`: HIGH only).

## Grass and wind

Grass (TASK-057) is cosmetic and fully in the view layer. `GrassPlanner` (pure, static; hash-seeded RNG, never `GameState.rng`) plans the clumps of one 4 x 4 world-unit chunk (`plan_chunk`): density per terrain (plains 90, hills 50, forest 25 per unit², none on water, the shore band or slopes above 0.5), scaled by the quality `grass_density`. `GrassField` (a `Node3D` owned by `MapView`) builds one `MultiMeshInstance3D` per chunk lazily – the first time the camera target (`MapView.set_camera_target`, fed by `BattleController`) comes within 20 units, one chunk per frame, rescanning only after the target moved – and keeps it. Chunks use `visibility_range_end` 14 with a 3 unit margin and `VISIBILITY_RANGE_FADE_SELF`, so grass fades out with distance (measured from the chunk centre) and costs nothing far away; they cast no shadows. The total is capped at `GrassPlanner.INSTANCE_BUDGET` (the density is cut back if the map would exceed it). `GrassMesh` is the 3-card clump, `GrassTexture` a procedural neutral grey blade card; the hue is the per-instance colour, the mean linear albedo of the `TerrainSplat` layers (`TerrainTextures` `average_colors`) weighted like the terrain shader, cached per 0.5 unit cell. Clump size is `0.07 x 0.05 x VisualScale.grass_scale()` (the `grass_scale` key follows the preset's `bush_scale`).

Open-ground vegetation (TASK-070). All tunables are look data: `LookPreset.meadow()` returns `MEADOW_OFF` (every feature off – the `current` preset reproduces the TASK-057/061 output exactly) merged with the active preset's `"meadow"` entry; planner functions take that dictionary as an argument (empty = the active one). `GrassPlanner` clumps carry `kind` (`Kind.SHORT / TALL / DRY_STALK / NETTLE`) and `height` (vertical multiplier, at most 1.5 in any preset). The kind comes from noises in world space (`GroundNoise.macro_k` for dry areas = the dry grass of the ground texture, `patch_k` for tall-grass patches, `moisture_k` for the bare dirt patches that also thin the grass) and from position hashes (`GrassPlanner.hash01`), never from extra RNG draws, so the TASK-057 positions do not move; forest edges (`forest_edge_distance`) get a tall-grass bonus and nettle, a radius around each tile centre stays short grass so units remain readable. `GrassPlanner.kind_color` blends the ground colour towards the kind's colour; `GrassField.clump_transform` scales the instance `(s, s * height, s)` and `GrassField.max_clump_height()` (used by `GroundOverlay.depth_pull()`) includes the tallest multiplier. Meadow flowers: `GrassPlanner.plan_flowers` (own RNG stream, seven draws per candidate) places small single-species clusters on plains (and sparsely on hills); `GrassField` builds a `Flowers_<x>_<z>` `MultiMeshInstance3D` next to each grass chunk (same clump mesh, `GrassTexture.flower_card`, `grass.gdshader` with `flower_mode`, same ranges, no shadows) and `instance_count()` counts both; the budget estimate reserves a flower share. LOW builds neither.

Ground overlays (unit marker rings and fills, reach / range / attack / hover washes) are lower than the grass, so they all use `GroundOverlay.material` (`assets/shaders/ground_overlay.gdshader`): the vertex shader pulls them towards the camera along the view ray by `GroundOverlay.depth_pull()` (tallest clump height / sin of the closest default camera pitch). The screen position is unchanged, only the depth, so overlays draw over the grass but stay hidden behind trees, units and ridges. Only rings and outlines get the pull; fills (`GroundOverlay.material(color, false)`) keep normal depth, because they lie under the unit models and a pull would tint the lower half of a model; they are `ground_only` instead – the shader compares the fill with the scene depth reconstructed to world Y and tints only the terrain, not wheels, tracks, boots or grass standing in the fill.

`Wind` registers the global shader parameters `wind_direction`, `wind_strength`, `wind_speed` at runtime (`RenderingServer.global_shader_parameter_add`, not in `project.godot`; strength 0 when the quality's `wind` is false). `assets/shaders/wind.gdshaderinc` reads them (`wind_offset`) and is shared by `grass.gdshader`, `foliage.gdshader` (trees, which also use its `wind_flutter`) and the later undergrowth shader. Under the headless dummy renderer the globals do not exist, so tests only check `Wind.strength()`.

## Trees

Trees (TASK-060) are cosmetic and view-only; `ScatterPlanner` still plans them (placement, counts and the high-ground conifer rule unchanged). `TreeSpecies.pick(tree)` (pure, static, a hash of the planned `position` and `k`, no RNG object) turns a planned tree into `{species, variant, custom}`: conifers become pine (60 %) or spruce (40 %), the others birch (35 %), oak (30 %) or alder (35 %); `custom` is the instance's `INSTANCE_CUSTOM` (r hue shift +-0.03, or +0.04..0.07 on the 1 in 25 yellower "autumn" deciduous tree; g value x0.85..1.1; b saturation x0.9..1.05; a wind phase). `TreeMeshes` (pure, cached, deterministic from `(species, variant)`, 3 variants per species, base at y = 0) builds one `ArrayMesh` with two surfaces per tree: bark (a tapered lathe trunk closed by a cap inside the crown, tapered branch rods) and leaves (LOD0: 60-120 alpha-scissor cards for deciduous crowns on lobes at the branch tips, 40-100 needle cards for conifers – spruce in drooping whorls, pine as flat tufts on short upper branches; LOD1: three jittered icosphere lobes with the hidden triangles dropped, or a cone stack). Crown normals are bent outwards from the crown centre; vertex colour r = AO, g = per-card flutter phase, b = 1 on leaves / 0 on bark. LOD0 is 230-341 triangles per tree on average per species, LOD1 26-155. `LeafTexture` paints the neutral-grey cards (`cluster` for leaves, `needles` for conifers; alpha 0/1, procedural – no CC0 textures are used).

`TreeField` (a `Node3D` owned by `MapView`, built in `MapView.build()` after `Wind.setup`) groups the map and backdrop trees into 8 x 8 unit chunks and makes one `MultiMeshInstance3D` per chunk x species x variant x LOD that has instances, origin at the chunk centre. LOD0 nodes: `visibility_range_end` 30, margin 4; LOD1 nodes (one mesh per species): `visibility_range_begin` 30, margin 4; both `FADE_SELF` and shadow casting (the card shadows are alpha-scissored). Backdrop trees more than `BACKDROP_LOD0_REACH` (14) units outside the playable tiles get only a "far" LOD1 node without a range: that keeps the LOD0 triangles of all chunks within 41 units (30 + 4 + `CameraMath.MIN_DISTANCE`) of any playable tile centre under 1 100 000 (default map: ~1 050 000 with scrub, was ~702 000 before TASK-061; tested). Instance size is `VisualScale.tree_scale()` (`TreeField.tree_transform`). LOW (`foliage = false`) builds no trees. `assets/shaders/foliage.gdshader` (one material per species and LOD) shades both surfaces: species leaf colour shifted per instance in HSV, alpha scissor 0.5 with alpha to coverage under MSAA, `BACKLIGHT` 0.35 x leaf colour, bark with procedural streaks (birch: light with dark marks); wind: the whole tree sways with `wind_offset(instance origin, y / 0.3, phase)` and leaf cards flutter with `wind_flutter` (at most 0.003 world units), both from the shared include. Scrub (TASK-061: species `shrub` and `undergrowth`, planned by `ScatterPlanner` as `edge_shrubs` / `ground_cover` with a `species` key, built from `TreeMeshes.SCRUB`) goes through the same field with shorter LOD0 ranges (`TreeField.SCRUB_LOD_DISTANCE`); undergrowth and backdrop trees cast no shadows; the wind only moves trees within `wind_distance` (24, faded over 8) of the camera, LOD1 crowns not at all. Thickets on open ground (TASK-070: a shrub with two undergrowth plants at a tile border, `ScatterPlanner.plan_tile_meadow`, output key `meadow_scrub`, own RNG stream, map tiles only – not the backdrop – and absent under `current` or on LOW) go through the same field. Bushes and rocks still use `FoliageMeshes`. Distant forest: real backdrop scatter only within `MapView.BACKDROP_SCATTER_REACH` (4) of the playable mesh; beyond it `BackdropCanopy` draws a cheap shell over the backdrop lattice (forest share of the nearest border tiles as vertex colour r, faded in over 1.5..5 units) with `assets/shaders/canopy.gdshader`, which paints jittered Voronoi crowns in the species colours (a crown is dropped when its hash exceeds the cover, so edges are ragged). `tools/screenshot.sh` can aim at a world point (`SCREENSHOT_FOCUS=<x>,<z>,<yaw>,<distance>`) and time frames (`SCREENSHOT_MEASURE_FRAMES=N` prints `Frame time: avg X ms, max Y ms over N frames`, vsync off).

## Ground marks (decals)

Tracks, craters and scorch (TASK-058) are cosmetic and view-only; no new event types. `GroundMarks` (pure, static) plans them: `track_segments(path_world, unit_class, unit_scale)` (tank = tread strips 0.42 wide, `mlrs` = tyre strips 0.34, infantry none; widths scale with `VisualScale.unit_model_scale() / 1.3`), `craters` / `impact_scorch` for indirect fire (attacker range >= 2, distance >= 2, not a counter), `death_scorch`, `reveal_fractions(points, path_time, rear_offset)` (share of each path segment's track mark that is drawn when the unit has walked `path_time`: from the start up to the unit's position minus `TRACK_REAR_OFFSET` 0.2, everything at the end) and `GroundMarks.Pool` (the `decals_max` cap: oldest track/tyre mark goes first, then craters, scorch last). Randomness is a hash of the view's own event serial, never `GameState.rng`. `DecalTextures` (static, cached) paints the albedo+alpha images. `GroundMarksView` (a node owned by `BattleController`) makes one `Decal` per mark; `BattleController` feeds it at the moment the matching animation plays (track marks are created at the start of the move, hidden, and grown by a tween with the same timing as `UnitView.move_along` – `GroundMarks.reveal_fractions` of `MoveAnimation.path_time` – so the visible end sits just behind the unit; the tween's last step reveals everything, so nothing stays half drawn; track decals have no fade-in; a decal evicted from the pool meanwhile is ignored; `GroundMarksView.add_growing_tracks` / `set_reveal`: the box never changes, the texture is swapped for a cached copy with the alpha cut at 1/32 steps of the length (`DecalTextures.revealed`), so the tread pattern never stretches; craters at the hit / last rocket impact, scorch when the death starts). Decals project onto visual layers 2 (terrain and backdrop, `MapView.TERRAIN_VISUAL_LAYER`) and 3 (grass chunks, so the blades are tinted rather than hiding the mark); units, trees, bushes and rocks stay on layer 1 and are never covered. Camera and light cull masks are the defaults. Decals are not verified on the Compatibility renderer (LOW on the WSLg build). `tools/screenshot.sh` shows them with `SCREENSHOT_MARKS=<unit id>` (demo marks around that unit, no animation).

## Units and factions

`UnitDefinition` (`src/core/data/`, one `data/units/<id>.tres` per real unit) holds `id`, `display_name` (real designation, or a translated descriptive name for squads), `short_name` (label, ≤ 6 characters), `unit_class` (`infantry` / `tank` / `mlrs`, ids from `docs/design/units/classes.json`), `mobility` (`foot` / `wheeled` / `tracked`, from the catalog) and the combat stats (`max_hp`, `move_points`, `attack`, `defense`, `attack_range`), derived by GDD "Stat derivation rules". Core rules read only the combat stats; `unit_class` and `mobility` group shared behaviour (presentation: volleys, locomotion, model contract – TASK-039b). `test_unit_catalog_consistency.gd` checks every unit against its catalog entry (`real_name`, `class`, `mobility`, roster factions ⊆ `operators`).

`FactionDefinition` (`src/core/data/`, instances in `data/factions/*.tres`) holds a faction's `id`, `display_name` (translation key), `short_name`, `roster: Array[UnitDefinition]`, `default_force: Array[UnitDefinition]` (the default battle's units in spawn order, each in the roster) and a Presentation group (`color`, `ink_color`, `camo`, `vest_color`) that core/AI never read. `FactionRegistry.get_faction(id)` / `all()` / `ids()` / `has_faction(id)` look them up (explicit path table, see ADR 0007). Each player has a faction id in `GameState.player_factions` (default `FactionRegistry.DEFAULT_IDS` = `poland`, `russia`); the view gets everything faction-specific from `state.faction_of(player_id)` – never from owner-indexed constants. `Scenario.default_battle(seed, factions)` assigns them and spawns each player's `default_force` in list order: range-1 units fill the front slots, the others the back slots (`Scenario.FRONT_SLOTS` / `BACK_SLOTS`; a force larger than the slots → `push_error`, extra units skipped). The map doesn't depend on the factions (spawn tiles are forced to plains); unit ids follow the spawn order, so they depend on the forces. Units outside the owner's roster are skipped. Balance between factions comes from `default_force` (unit counts), never from unit stats; `MatchRunner.play(seed, max_turns, factions)` / `tools/simulate.sh --factions=<p0>,<p1>` measure it.

## Replays and match records

A match is fully described by `scenario + seed + executed commands` (state is never serialized).

- `Command.to_dict()` gives a JSON-compatible form (`{"type": "move", "unit_id", "target": [q, r]}`, `{"type": "attack", "attacker_id", "target_id"}`, `{"type": "end_turn"}`); `CommandCodec.from_dict(d)` (`src/core/commands/command_codec.gd`) rebuilds it and returns `null` on anything unknown or malformed. JSON parses every number as a float: integral floats become `int`, non-integral / non-finite / beyond ±2^53 values, bools and strings are rejected. A new command type = `to_dict()` + a branch in `CommandCodec` + a codec test.
- `MatchRecord` (`src/core/match_record.gd`): `version` (2), `scenario`, `seed`, `factions: Array[StringName]` (required), `commands: Array[Dictionary]`; `from_simulation(sim, seed)` copies `sim.history` and `sim.state.player_factions`, `to_json()` / `from_json(text)` (`null` on invalid JSON, version ≠ 2 or malformed fields; extra keys ignored). `parse_json(text)` returns `{"record", "error"}` with a readable message instead – e.g. version 1 records (before TASK-039a's real units) are reported as unsupported (ADR 0009). `MatchRecord.normalize(value)` turns integral floats of parsed JSON back into ints for comparisons.
- `Replay.run(record)` (`src/core/replay.gd`) builds the scenario's state from the seed (only `"default_battle"` → `Scenario.default_battle(seed, record.factions)`) and executes each decoded command through `GameSimulation.execute`. Errors: `unknown_scenario` (index -1), `invalid_factions` (unknown id or not two ids; index -1), `invalid_command` (codec returned `null`), `diverged` (rejected; `reason` = the `validate()` code).
- `GameState.snapshot()` is the comparable state description (turn, current player, winner, `rng_state`, units sorted by id incl. dead). `rng_state` is stored as a **String** because the 64-bit RNG state does not survive a JSON double.
- Regression fixture `tests/fixtures/replays/default_battle_12345.json` (AI vs AI, seed 12345, until `game_over` or turn 30) = record + `"expected_final"` snapshot; `test_replay.gd` replays it. After an *intended* rule change, regenerate it with `tools/make_replay_fixture.sh` (headless `tools/make_replay_fixture.gd`) and commit the new file.

## Coordinates

Hex grid, axial coordinates `(q, r)` as `Vector2i`, "pointy-top" layout. World ↔ tile conversions in `Hex.to_world` / `Hex.from_world`. Rectangular maps are generated in offset layout (`MapGenerator.offset_to_axial`).

## Events

| type | fields | emitted by |
|---|---|---|
| `unit_moved` | `unit_id`, `from`, `to`, `path` (`Array[Vector2i]`: tiles walked, excludes `from`, ends with `to`) | MoveUnitCommand |
| `turn_ended` | `player` | EndTurnCommand |
| `turn_started` | `player`, `turn` | EndTurnCommand |
| `unit_attacked` | `attacker_id`, `target_id`, `damage` (before clamping HP at 0), `target_hp`, `counter` (bool; true when the event is a counterattack by the target) | AttackCommand |
| `unit_died` | `unit_id` | AttackCommand |
| `game_over` | `winner` (only one player has living units left) | AttackCommand |

View-only annotations: `BattleController` adds `view_duration` (seconds) and `view_fx` (`rocket_volley`, `direct_fire`) to the copies of events it queues for playback (see `EventQueue`); the simulation's events are never modified. `rocket_volley` (TASK-074) lasts the aim / deploy / stow steps plus the full salvo (`SalvoTiming.salvo_duration`: one rocket per tube, the count, ripple interval and flight time from `VolleyPlayback.salvo_plan`, computed when the event is emitted). Volleys are left out of the burst speed-up (`EventQueue.burst_duration`, used by `begin_burst`) and play at `EventQueue.playback_speed` = at most `MAX_VOLLEY_SPEED` (1.5x) even in a fast burst, so the salvo's pauses stay visible in an AI turn; `pending_duration` still counts them. `direct_fire` (TASK-047) marks a `unit_attacked` whose attacker has a `turret_traverse` model: `TURRET_AIM_DURATION` (0.5 s) turret traverse and gun elevation, the target's hit (`ATTACK_DURATION`), 0.5 s back to the front (1.4 s; +`AIM_DURATION` for a limited traverse, where the hull turns first); counterattacks play the same with the counter-attacker aiming. Units without a turret keep the hit-only playback.

Wrecks (TASK-065) are view-only too; no new event types. A vehicle's `unit_died` plays `UnitView.play_death(on_wreck)` over the unchanged `EventQueue.DEATH_DURATION`: flash light, death burst (HIGH), camo shader instance uniform `burnt` 0 -> 1, the model's `Turret` pivot knocked askew (`WreckPlan`: yaw 20-35 deg, tilt 6-10 deg from a hash of the unit id) and launcher pods stowed; at the end `WreckField.adopt` moves the body into a `WreckView` (smoke column + first-turn fire light only with the `particles` quality flag). `WreckLife` (pure) counts `turn_started` events (smoke thins after 1, stops after 3) and hides the wreck when `unit_moved` ends on its tile (`BattleController` relays both to `WreckField`). Infantry leaves no wreck (`WreckPlan.leaves_wreck`). Wrecks have no collision and are not in the units dictionary, so hover and picking (which read `GameState.unit_at`) ignore them.

## Localization

All UI strings live in `assets/i18n/strings.csv` (columns `keys,en,pl`); Godot imports it into `strings.<locale>.translation`, registered in `project.godot` (fallback `en`). Keys are the English source strings (gettext style): `tr("Your turn")`, format strings are keys too and values are substituted after translation: `tr("Turn %d") % turn`. Static/pure helpers without `Object.tr()` call `TranslationServer.translate(key)`. Labels whose text is composed in code set `auto_translate_mode = Node.AUTO_TRANSLATE_MODE_DISABLED` so the text is not translated twice. Every new UI string = a CSV row with `en` + `pl` (`tests/unit/test_localization.gd` checks coverage and placeholders). To try Polish, set the project setting `internationalization/locale/test="pl"` (do not commit it).
