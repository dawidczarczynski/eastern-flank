# Tools reference

Full descriptions of the command-line tools (moved out of CLAUDE.md to keep the startup context small; CLAUDE.md keeps the one-line summaries).

- `tools/check.sh` – lint + all tests. **Run it before reporting that a task is done.**
- `tools/check.sh [--full]` – lint + tests + tool tests; by default without the slow tests listed in `tests/slow_tests.txt` (8 tests of 8 s or more, regenerated by `tools/shard_weights.py`), `--full` runs them too
- `tools/test.sh [--fast] [--verbose] [filter]` – headless tests only (`--fast` skips `tests/slow_tests.txt`) (e.g. `tools/test.sh test_commands`); prints only failures, script errors and the summary, the full Godot log is in `.test.log`; without a filter the test files run in up to 4 parallel Godot processes , balanced by `tests/shard_weights.json` (`JOBS=N` overrides, `TEST_TIMES=1` prints per-test times; refresh the weights after big test changes: `TEST_TIMES=1 tools/test.sh --verbose >/dev/null; tools/shard_weights.py`)
- `tools/lint.sh [--fix|--all]` – gdformat + gdlint; checks only files changed since their last clean run (stamps in `.lint-cache`) in parallel, `--all` rechecks everything
- `tools/backlog.py [--fix]` – checks (or fixes) `blocked`/`ready` in docs/tasks/BACKLOG.md and the task files against the hard dependencies, and fails when a row's status differs from its task file's Status line (--fix keeps the further-along one); run by `tools/check.sh`
- `tools/devtools.sh [--port=8760]` – devtools hub for the human: one local page (127.0.0.1) that starts the web tools below (backlog viewer, unit catalog – or reuses ones already running) as tabs and runs the command-line tools (check, tests, lint/backlog fix, simulate, screenshots, render unit, teaser video, game, editor) as jobs with live output and the images they wrote; a **Claude** tab chats with Claude Code sessions in the repo, and the backlog's task panel starts `/implement-task` with "▶ Implement with Claude" (ADR 0017: behaves like the IDE session – auto mode and your settings, except that task sessions run the orchestrator on `--model sonnet`, permission prompts and questions answered in the page, Stop/Esc interrupts); the sidebar shows the subscription's 5-hour / weekly usage live; commands are fixed templates in `tools/devtools/registry.py` (add a new tool there); Python tests run in `tools/check.sh`
- `tools/task_cost.py [--projects-dir=…] [--out=docs/tasks/task_costs.json]` – Claude usage per task from the Claude Code transcripts (`/implement-task` sessions + their subagents) as one weighted cost (tokens × API list price per model family, "API-equivalent $"); merges with the committed file so tasks whose transcripts were cleaned up stay; run by devtools on start and the backlog view's ↻ Costs button
- `tools/backlog_view.sh [--port=8766]` – local web view of docs/tasks/BACKLOG.md (Python stdlib, 127.0.0.1 only): sort by any column, filter by status / model / text, task files rendered in a side panel, dependencies and unblocked tasks highlighted; Order view (`?view=order`, key O): the notes' `Recommended order of the open `tag` tasks` list as swimlanes, one per numbered step (→ after, ‖ parallel); Tree view (`?view=tree`, key R): one branch per topic (the `Name (TASK-A … TASK-B, …)` paragraphs below the table, or a `- **Topic**:` line in a task file), a left-to-right diagram with each task right of the dependency it builds on (finished tasks fold into small tags), hover lights up a task's links; the page follows changes to BACKLOG.md and the task files live (polls every second); **Usage** column (tools/usage_forecast.py): finished tasks show their actual cost, open ones a forecast range from comparable finished tasks (same model × layer group, orchestrator run on sonnet, scaled by size) – as size S–XL until calibrated, then as `~15–30 % · ~3–6 % wk` of the subscription windows, ⚠ when it may not fit the rest of the live 5-hour window; calibration samples come from devtools task sessions (`docs/tasks/usage_calibration.jsonl`, committed); Python tests run in `tools/check.sh`
- `tools/run.sh [--editor] [--scene=staff_map|battle|menu] [--side=nato|russia] [--debug]` – run the game / editor (needs a GUI; usually done by the human); `--scene=` opens a scene directly instead of the menu (the operational staff map, TASK-093a) **Debug keys on the staff map (`--debug`)**: F9 politics / contact-map panels, `--terrain-viewer` (in the game: main menu → DEVTOOLS (`--debug`) → **TERRAIN VIEWER**; TerrainViewController): the bare staff map – no formations, HUD, front line or orders – where a click on any hex opens the **terrain of that place as the tactical battle draws it** (the 40 × 30 cut of the tactical layer around the hex, `TerrainViewSetup`; no units, no battle HUD, no rules), with the battle camera and **G** for the grid; **Esc** goes back to the map, and Esc on the map to the main menu. **F10 quick contact** – the current player's formation nearest to an enemy jumps next to it and the contact battle starts at once (`ContactRules.force_contact`), so a real operation battle is one key press away.
- `tools/run.sh --scene=arena` (also `run_windows.sh`, and the **Arena** command in devtools) – **dev arena** (`ArenaController`, scenes/battle/arena.tscn): an empty flat 18×11 map where you place units of both sides and command them freely, to try animations and effects (e.g. barrel-artillery barrages) without playing a battle. Keys: `1` command (normal move / attack orders), `2` place (left click puts the unit picked in the panel on a tile), `3` remove, `4` refill HP / moves / attacks of all units, `Tab` other side, right click leaves a tool; the panel on the left also picks each side's faction and clears the arena. In a `--debug` run the main menu also has a **DEVTOOLS** page (TASK-185) with an ARENA button. Hot seat: End turn (Enter) hands the command to the other side; no AI, no objectives, the battle never ends. Placing / removing edit the state directly (bench only, not recorded); orders still go through the normal commands. **Effects** (TASK-186a): the collapsible *Effects* section of the panel has a slow-motion slider (0.1..1.0, `Engine.time_scale`, back to 1.0 when the arena is left) and one slider per effect tunable of `DevTunables` (barrage elevation / shell count / interval / flight, tracer, landing disc, MLRS rocket count / interval / flight / apex, impact particle amounts, launch flash size, camera shake) with a per-value reset and *Reset all*; values act on the next attack, are kept for the session and count only inside the arena. **Fire again** replays the last attack (same shooter, target and visuals) as a view event: no command runs and the state is untouched; it greys out when a unit is gone. **View and unit editor** (TASK-186b): the *View* section picks graphics quality (Auto / LOW / HIGH), unit scale (current / true size) and look preset (rebuilds map and units in place), toggles the grid, an FPS overlay ("NN FPS  X.X ms", top right) and *unlock camera distance* (min distance halved, max doubled); *Ignore line of sight* (Tools section) lets direct fire hit through blocked sight lines; the *Selected unit* box edits HP, moves, dug-in and ambush of the selected unit (bench only, not recorded). **Unit stats**: the *Unit stats* section edits the selected unit's max HP, move points, attack, defense, full / max / min range (metres, one step = one hex) and fire mode (direct / indirect); the unit gets its own copy of the definition (data files and other units of the type are untouched), ranges stay ordered min <= full <= max, *Reset unit stats* restores the shared definition. The panel is a HUD v3 `FramedPanel` (tab ARENA / DEV BENCH) with collapsible sections (Tools, Armies, Selected unit, Unit stats, View, Effects) and scrolls when the window is low. The DEVTOOLS page has plates for quality, scale, look and the FPS overlay; they apply when the arena opens. Switches count only inside the arena. Screenshots: `SCREENSHOT_SCENE=arena SCREENSHOT_ARENA=<owner>:<unit type>:<col>:<row>,... SCREENSHOT_SALVO=1,2 tools/screenshot.sh` (unit ids 1, 2, … in placement order)
- `tools/run_windows.sh [--editor] [--import] [--local] [--scene=…] [--side=…] [--debug]` – run with the Windows Godot build from WSL (GPU rendering; the WSLg build falls back to slow software rendering); `--local` first mirrors the game files (rsync, ~120 MB) to `%LOCALAPPDATA%\eastern-flank\run-copy` and runs from there – Windows reads the WSL path slowly, the battle scene's scripts load in ~4.5 s instead of ~18 s
- `tools/screenshot.sh [out.png] [--frames=N] [--windows|--linux]` – render the battle scene to a 1280×720 PNG (default `.screenshots/battle.png`) and read it with the Read tool to check visual changes (HUD states: `SCREENSHOT_SCENE=staff_map` renders the operational staff map (`SCREENSHOT_STAFF_MAP=zoom:min|max|<factor>,decisions[:confirm],focus:<col>:<row>,hover:<col>:<row>,grid,side:<0|1>,select:<formation id>,hovercounter:<formation id>`; prints `Staff map built in N ms`); `SCREENSHOT_SHOTS=hover:2,select:2,toast,targeting,banner` captures several in one run as `<out>_<state>.png` – one ~30 s run instead of one per state; scale study (TASK-110): `SCREENSHOT_SCALE_PRESET=true` puts units, trees, scrub, rocks and grass at real size from `MapScale`, `SCREENSHOT_MIN_DISTANCE=<0.05-7>` lets `SCREENSHOT_CAMERA` / `SCREENSHOT_FOCUS` go closer than the game's zoom limit; `SCREENSHOT_TIME_LIMIT=<s>` raises the 60 s run limit (the Suwałki battle needs ~120–180 s); more debug variables are listed in the header of tools/screenshot.gd); under WSL it uses the Windows Godot console build (GPU, D3D12, Forward+ with SSAO – what the human sees) when found, `--linux` forces the WSLg software renderer (Compatibility look)
- `tools/menu_backdrop.sh [--only=map|battle]` – re-render the two stills behind the main menu (`assets/menu/staff_map.png`: staff map without HUD, `assets/menu/battle.png`: the Homar-K salvo frame of the teaser, `tools/teaser.sh --still=<s>`; both 1792×1008 GPU renders, the battle one takes a few minutes); `tools/readme_screenshot.sh` runs only the map part (the battle part, i.e. the teaser, only with `MENU_BACKDROP_BATTLE=1`), so it follows the graphics work – commit the PNGs (and their `.import`) with the change. `SCREENSHOT_RESOLUTION=WxH` makes `tools/screenshot.sh` render another size; the staff-map token `nohud` hides the whole HUD
- `tools/perf.sh [--no-breakdown | --only=trees,shadows] [--resolution=1920x1080] [--scenario=<name>]` – frame cost of the battle scene on the GPU: prints the device, `Frame time: avg / max`, `Render: draws, tris, GPU ms, render CPU ms`, then a breakdown (`tools/perf_profile.gd`) that switches one part of the picture off at a time (trees, bushes, terrain, units, shadows, SSAO, SSIL, MSAA, ...) and prints what it saves, sorted. Run it before and after adding a visual detail; the budget is 16.6 ms at 1920×1080 on the target GPU. Camera through `SCREENSHOT_CAMERA` / `SCREENSHOT_FOCUS`; other `tools/screenshot.sh` options pass through. The rows overlap (hidden trees cast no shadows), so they do not add up to the frame; a temporary experiment is one more `_cases.append` in `perf_profile.gd`
- `tools/bench_large_map.sh [--scale=1|4|16 | --all] [--quality=low|high] [--windows|--linux]` (TASK-072a) – large-map benchmark: the Suwałki battle map tiled to 1×/4×/16× its area (`MapTiler`, mirrored at the seams; roads and rivers are not copied) and built in a bare scene (map, sun, environment, camera; no units or HUD) by `tools/bench_large_map.gd`, one Godot process per scale. Prints a build table (hexes, `MapView.build` s, chunk prebuild s – every chunk the rings ask for around the first camera, TASK-072b; before that it was the grass prebuild only –, static MB, video MB, MultiMesh instances, k triangles, draws) and a frame table (avg / max ms over 120 frames at camera distances 46 / 24 / 7 / 1.2, plus a 10 s pan sweep with the count of frames > 33 ms). Vsync off. Use `--windows` (GPU, default under WSL) – the Linux software renderer crashes on it. `BENCH_TIME_LIMIT=<s>` per scale (default 900); a failing scale prints `FAILED <scale>` with the log tail. Not part of `tools/check.sh`
- `tools/readme_screenshot.sh` – re-render the README shots `docs/images/gameplay.png` + `staff_map.png` and the menu staff-map backdrop (`tools/menu_backdrop.sh --only=map`; `MENU_BACKDROP_BATTLE=1` adds the slow teaser battle backdrop) (fixed close-up framing, same requirements as `tools/screenshot.sh`)
- `tools/render_unit.sh <unit_id> [--faction=<id>] [--views=side,front,top,three_quarter] [--reference=path] [--out=sheet.png] [--soldier=<i>] [--windows|--linux]` – render one unit model alone on a 1 m model-space grid (orthographic side/front/top at the same scale + three-quarter) next to a reference image into `.screenshots/units/<id>_<faction>_sheet.png`; last stdout lines are `Render saved`, `Stats` (AABB in m, triangles, mesh instances, pivots) and `Real` (vs. the unit catalog); used by `/model-unit`; renders with the same Godot build choice as `tools/screenshot.sh`. `tools/render_unit.sh --weapon <means_id> [--views=…] [--reference=path] [--out=sheet.png]` renders a strike weapon model (`WeaponModels`, src/presentation/models/weapons/, TASK-144) on the same sheet (built in metres, scaled to the 1 m grid and set on the ground) into `.screenshots/units/<id>_sheet.png`, with the `Real` line from `docs/design/units/weapons/<id>/unit.json` (tools/render_weapon.gd)
- `tools/analyze_glb.sh <unit_id> [--front=+x|-x|+z|-z] [--force] [--no-measure] [--views=…] [--out=sheet.png] [--windows|--linux]` (TASK-179) – a Meshy GLB as the unit's reference instead of photos: loads `docs/design/units/units/<id>/reference.glb` (not in git), normalises it to the catalog dimensions (model faces +X, narrower end = front unless `--front` names the GLB axis pointing forward, stands on y = 0, centred, uniform scale so the length equals `overall_length` / `hull_length`; a foot unit: its height) and renders it like `render_unit.sh` into `<unit folder>/reference_views/glb_{side,front,top,three_quarter}.png` + `glb_sheet.png`; writes `normalisation.json` (yaw, scale, size, warnings) next to the GLB. Width / height more than 25 % off the catalog (height ignores the top 2 % of vertices: antennas, raised barrels) fail the run (exit 1) unless `--force`. `tools/render_unit.sh <id>` uses `reference_views/glb_side.png` as the default `--reference` when the unit has no photo. Implementation: `tools/glb_reference.gd`, `tools/render_glb.gd`.
  - **Batch** (TASK-183): `tools/analyze_glb.sh --all [--force] [--no-measure]` analyses every unit with a `reference.glb` whose `measurements.json` is missing or stale (the GLB's sha256 differs from the stamp `reference.glb.sha256`; with no stamp, an older `measurements.json` counts as stale) and ends with a table of the normalisation and measurement warnings per unit; exit 1 if any unit failed. `/model-unit --queue` then models the `ready_for_model` GLB units one after another.
  - **Measurements** (TASK-180, automatic; `--no-measure` skips them, ~20 s for a 2 M triangle Meshy GLB): writes `<unit folder>/measurements.json` (commit it; the GLB stays out of git) in the model files' frame (metres, `x` from the hull nose rearwards, `h` above the ground, `hw` half width). `profiles.hull` / `profiles.above_deck`: height (`h`), half width (`hw`; above the deck also the lowest point `h0`) every 0.1 m along x. `constants`: `DECK_H`, `ROOF_H` (largest up-facing area in / above the deck band), `HULL_LENGTH`, `GUN_OVERHANG`, `REAR_OVERHANG`, `UPPER_HW` (band 0.45 m below the deck), `LOWER_HW` / `TRACK_Z` / `TRACK_WIDTH` (inner / centre / width of the tracks or tyres near the ground), `TURRET_X` / `TURRET_RING_R` / `TURRET_FRONT` / `TURRET_REAR` / `TURRET_HW` (turret base layer 0.05–0.25 m above the deck; the ring radius is that of a disc of equal area), `TRUNNION` (where the barrel meets the mantlet: the real trunnion lies a bit behind it), `GUN_LENGTH`, `GUN_ELEVATION_DEG`, `ROAD_WHEELS` (`count_per_side`, `radius`, `h`, `x` list; from separate round components, or – fused Meshy meshes – from the side depth map with low confidence, which may count the sprocket / idler). Every value has a `confidence` 0..1 and a `note`; values below 0.5, catalog conflicts (> 5 % off `hull_length`, `width`, `height`) and an elevated gun are listed in `warnings` (also printed as `MEASUREMENT WARNING`). A foot unit gets only `HEIGHT`, `WIDTH`, `DEPTH` and the proportions. Heuristics: compare with the model constants and judge large differences, never paste them blindly. Implementation: `tools/glb_measurements.gd` (pure, tested in `tests/unit/test_glb_measurements.gd`)
- **Unit catalog – reference GLB** (TASK-182): `tools/unit_catalog.sh` uploads a GLB (`PUT /api/units/<id>/reference_glb`, raw `model/gltf-binary` body, ≤ 1 GB) and queues an `analyze` job (`tools/analyze_glb.sh <id>`, runs without the Claude CLI; Jobs screen shows the log) whose views and warnings appear on the unit screen. A GLB satisfies the image requirement of `ready_for_model` and lowers the silhouette feature minimum to 1 (docs/design/units/README.md, "Reference GLB"). Python tests: `python3 -m unittest discover -s tools/unit_catalog -p 'test_*.py'`.
- `tools/compare_silhouette.sh <unit_id> [--min-iou=0.90] [--pixel=0.02] [--front=+x|-x|+z|-z] [--faction=<id>] [--soldier=<i>]` (TASK-181) – replaces eyeballing the model against its reference GLB (`reference.glb`, see `analyze_glb.sh`): rasterises the game model's visible triangles and the normalised GLB orthographically (no rendering, headless, ~1 min for a 2 M triangle GLB; both meshes centred in x / z over their bounding boxes, standing on y = 0) into side / front / top masks at `--pixel` metres. Prints per view `iou`, both areas and their difference, saves `.screenshots/units/<id>_diff_<view>.png` (grey = both, red = only in the model, blue = only in the GLB) and ends with `IoU side=0.93 front=0.90 top=0.91 (min 0.90: ok)` plus the 3 largest mismatch regions (`Mismatch: side missing 0.31 m2: x 2.10..3.40 m, h 2.30..2.60 m, model -0.12 m high`; `extra` = only in the model, `missing` = only in the GLB, `+` / `-` the model's excess / lack). The GLB's front is taken from `normalisation.json` (what `analyze_glb.sh --front=` used) unless `--front` is given. Exit 0 when every IoU >= `--min-iou`, 1 below it or on failure, 2 invalid arguments. A GLB with an antenna or a raised barrel enlarges its silhouette (the model is compared as is). `--soldier=<i>` (also on `render_unit.sh`) keeps only a squad's `Soldier<i>`, at the origin facing +X (`--soldier-yaw=<deg>` turns it like the GLB's figure; the comparison scales it to the GLB's height: shapes, not sizes), to compare one figure with a one-soldier GLB. Implementation: `tools/silhouette.gd` (pure, tested in `tests/unit/test_silhouette.gd`), `tools/compare_silhouette.gd`
- `tools/teaser.sh [out.avi] [--still=<s>] [--resolution=1920x1080] [--fps=60]` – one-off promo video: the Homar-K's salvo destroys the T-72B3 in the default battle, scripted cinematic camera, fade in, game logo at the end, with the game's sound (forest ambience and birds, rocket launches, explosions); Godot Movie Maker mode (fixed frame rate) writes `.screenshots/teaser/homar_teaser.avi` (MJPEG, ~300 MB at 1080p60, ~2 min render); the camera path in `tools/teaser.gd` is hand-tuned for that pair (its header explains it and the `--spin` camera scout for other pairs); same Godot build choice as `tools/screenshot.sh`
- `tools/simulate.sh N [--seed=S] [--max-turns=T] [--factions=P0,P1] [--scenario=default_battle|objective_battle|command_points_battle|fire_support_battle|suwalki_battle|contact_battle] [--verbose]` – N headless AI-vs-AI matches: win rates, draws by the rules vs. matches cut by the harness `--max-turns`, rejected AI commands, average and longest match length, average and slowest AI turn time in ms (balancing; `contact_battle` = simulation-only 7 v 7 battalion contact at Suwałki, player 0 attacks, TASK-170b); `--factions` picks the players' factions (default `poland,russia`), `--scenario` the battle (default `default_battle`)
- `tools/simulate.sh N --mode=operation [--seed=S] [--max-rounds=R] [--scenario=<operation id>] [--battles=auto|played] [--out=file.csv] [--verbose]` (TASK-103a) – N whole operations AI-vs-AI (`OperationMatchRunner`, both sides `OperationalAiTurn`; default operation `suwalki_gap`, round cap R = the operation's `round_limit` data value, default 30; a smaller R ends the match by `round_limit` at that round). `--battles=auto` (default) auto-resolves every contact; `played` fights each as a headless tactical battle (slow, use a small N) and reports played-vs-auto winner agreement (e.g. 12 / 18). Report: per-side wins (by a rule / by score at the round limit), draws, win share of decided operations (those with a winner), endings by type (`collapse` / `threshold` / `nuclear` / `corridor_closed` / `annihilation` / `round_limit`; the victory rules are `OperationVictory`, TASK-107a), average length in rounds, average max escalation level, escalation steps caused per side, strikes fired / intercepted / installations destroyed, battles by resolution. `--out` writes a CSV with header `seed,winner,ending,rounds,max_level,battles`, one row per match. `--max-turns` / `--factions` are rejected in operation mode, `--max-rounds` / `--battles` / `--out` in tactical mode (exit 2); an unknown operation or unwritable `--out` exits 1.
- `tools/import_map.py [<bbox>] --center=<lat,lon> --size=30x24 --hex=250 --name=<id> --out=data/maps/<id>.tres [--offline] [--cache=DIR] [--profile=tactical|operational|layer]` – hex map from real geography (ADR 0018): Copernicus GLO-30 DEM + OpenStreetMap land cover, downloaded once into `~/.cache/eastern-flank/maps` (outside git), then offline and byte-identical; stdlib Python; `--profile=operational` (TASK-092a) makes the 5 km theatre map: 250 m lattice, GLO-90 (`--dem=glo30|glo90`), Overpass in 0.5° tiles (`--tile-deg=`, resumable, retried), sea filled from the coastline (`--sea-seed=lat,lon`), thresholds `--water-share --urban-share --forest-share --marsh-share --hills-relief`; country per hex (TASK-113) from `--countries=ISO:lat,lon,...` seed points (operational defaults PL / LT / BY / RU) and the borders-only tiles `bd1_*.json` (own download, `--offline` fails naming a missing one), also written as drawn border polylines `border_lines` (world units, simplified 0.1 hex); operational maps also get `place_names` / `place_positions` / `place_ranks` (TASK-112: OSM `place=city|town|village` nodes from their own tiles `pl1_*.json`, `--offline` fails naming a missing one; villages need `population` >= 1000, total <= 400); operational maps also get the graphic layers for drawing (TASK-126): `water` (1-bit), `cover` (8-bit class) and `relief` (8-bit hillshade, sun NW 45°, `--relief-z=4` exaggeration, 500 m pixels `--relief-step=2`) images of the 250 m lattice, stored as base64 PNGs in `layer_*_png` (`ImportedMap.layer_image`); the theatre's first download is ~1.9 GB / ~1.7 h, an offline import ~4.5 min and ~0.9 GB RAM (rebuild command in CREDITS); tactical maps and the layer also store a **land-cover raster** (TASK-108g, ADR 0028: one `LandCover.Kind` byte per `--cover-cell=16` m cell, the hex types counted on its cells; `--cover-cell=0` = none, the old lattice classification); `--profile=layer` (TASK-094b) writes a theatre-wide **tactical layer** for contact battles into the folder `--out` (`layer.tres` + 128 × 128 `chunk_<cx>_<cy>.tres`, `TacticalLayer`): 250 m hexes from the operational cache (op1 tiles + GLO-90) plus its own land-use tiles `lu1_*.json` (farmland / grass for FIELDS, `landuse_query`; same grid, retried, 5 s between downloads; the theatre's first download is ~0.9 GB / ~70 min; `--offline` fails naming a missing one), 16 m land-cover raster (sea filled on the 50 m lattice), DEM at 7 points per hex, hills from 10 m relief; the Suwalki theatre layer takes ~9 min offline and ~1 GB RAM (command in CREDITS); play the committed sample with `tools/run.sh --scenario=suwalki_battle`; `--colour` (TASK-192a, ADR 0031; tactical / layer only, `tools/import_map_colour.py`) adds the **satellite colour layer**: a Sentinel-2 L2A summer composite from the AWS COGs (Earth Search STAC; scene manifest `s2v1_<bbox>.json` and band files `s2/<scene>/<band>_L<level>.tif` in the cache, written once, `--offline` fails naming a missing one; `--s2-manifest=` reads a given manifest instead), corrected to sRGB and stored as baseline JPEG – 10 m on tactical maps (`--colour-cell`), 40 m in the layer with one JPEG window per chunk, quality `--colour-quality=85`; the first import downloads the small SCL band of every candidate scene and the colour bands only of the scenes it uses (Suwałki: 1 scene, ~240 MB of 10 m bands; the theatre: 40 m overview prefixes of 27 scenes; the theatre layer with `--colour` takes ~35 min); attribution in `data/maps/CREDITS`; Python tests (`tools/test_import_map.py`, fixtures re-made with `--make-fixtures`) run in `tools/check.sh`
- `tools/unit_catalog.sh [--port=8765]` – local web tool (Python stdlib, 127.0.0.1 only) for the human to collect real-unit references (facts, dimensions, images, factions) into `docs/design/units/`; it can run `/research-unit` and `/model-unit` as headless Claude Code jobs (ADR 0008); Python tests run in `tools/check.sh`
