# Tools reference

Full descriptions of the command-line tools (moved out of CLAUDE.md to keep the startup context small; CLAUDE.md keeps the one-line summaries).

- `tools/check.sh` – lint + all tests. **Run it before reporting that a task is done.**
- `tools/test.sh [--verbose] [filter]` – headless tests only (e.g. `tools/test.sh test_commands`); prints only failures, script errors and the summary, the full Godot log is in `.test.log`; without a filter the test files run in up to 4 parallel Godot processes (`JOBS=N` overrides, `TEST_TIMES=1` prints per-test times)
- `tools/lint.sh [--fix]` – gdformat + gdlint
- `tools/backlog.py [--fix]` – checks (or fixes) `blocked`/`ready` in docs/tasks/BACKLOG.md and the task files against the hard dependencies, and fails when a row's status differs from its task file's Status line (--fix keeps the further-along one); run by `tools/check.sh`
- `tools/devtools.sh [--port=8760]` – devtools hub for the human: one local page (127.0.0.1) that starts the web tools below (backlog viewer, unit catalog – or reuses ones already running) as tabs and runs the command-line tools (check, tests, lint/backlog fix, simulate, screenshots, render unit, teaser video, game, editor) as jobs with live output and the images they wrote; a **Claude** tab chats with Claude Code sessions in the repo, and the backlog's task panel starts `/implement-task` with "▶ Implement with Claude" (ADR 0017: behaves like the IDE session – auto mode and your settings, except that task sessions run the orchestrator on `--model sonnet`, permission prompts and questions answered in the page, Stop/Esc interrupts); the sidebar shows the subscription's 5-hour / weekly usage live; commands are fixed templates in `tools/devtools/registry.py` (add a new tool there); Python tests run in `tools/check.sh`
- `tools/task_cost.py [--projects-dir=…] [--out=docs/tasks/task_costs.json]` – Claude usage per task from the Claude Code transcripts (`/implement-task` sessions + their subagents) as one weighted cost (tokens × API list price per model family, "API-equivalent $"); merges with the committed file so tasks whose transcripts were cleaned up stay; run by devtools on start and the backlog view's ↻ Costs button
- `tools/backlog_view.sh [--port=8766]` – local web view of docs/tasks/BACKLOG.md (Python stdlib, 127.0.0.1 only): sort by any column, filter by status / model / text, task files rendered in a side panel, dependencies and unblocked tasks highlighted; Tree view (`?view=tree`, key R): one branch per topic (the `Name (TASK-A … TASK-B, …)` paragraphs below the table, or a `- **Topic**:` line in a task file), a left-to-right diagram with each task right of the dependency it builds on (finished tasks fold into small tags), hover lights up a task's links; the page follows changes to BACKLOG.md and the task files live (polls every second); **Usage** column (tools/usage_forecast.py): finished tasks show their actual cost, open ones a forecast range from comparable finished tasks (same model × layer group, orchestrator run on sonnet, scaled by size) – as size S–XL until calibrated, then as `~15–30 % · ~3–6 % wk` of the subscription windows, ⚠ when it may not fit the rest of the live 5-hour window; calibration samples come from devtools task sessions (`docs/tasks/usage_calibration.jsonl`, committed); Python tests run in `tools/check.sh`
- `tools/run.sh [--editor] [--scene=staff_map|battle|menu] [--side=nato|russia] [--debug]` – run the game / editor (needs a GUI; usually done by the human); `--scene=` opens a scene directly instead of the menu (the operational staff map, TASK-093a)
- `tools/run_windows.sh [--editor] [--import] [--scene=…] [--side=…] [--debug]` – run with the Windows Godot build from WSL (GPU rendering; the WSLg build falls back to slow software rendering)
- `tools/screenshot.sh [out.png] [--frames=N] [--windows|--linux]` – render the battle scene to a 1280×720 PNG (default `.screenshots/battle.png`) and read it with the Read tool to check visual changes (HUD states: `SCREENSHOT_SCENE=staff_map` renders the operational staff map (`SCREENSHOT_STAFF_MAP=zoom:min|max|<factor>,decisions[:confirm],focus:<col>:<row>,hover:<col>:<row>,grid,side:<0|1>,select:<formation id>,hovercounter:<formation id>`; prints `Staff map built in N ms`); `SCREENSHOT_SHOTS=hover:2,select:2,toast,targeting,banner` captures several in one run as `<out>_<state>.png` – one ~30 s run instead of one per state; scale study (TASK-110): `SCREENSHOT_SCALE_PRESET=true` puts units, trees, scrub, rocks and grass at real size from `MapScale`, `SCREENSHOT_MIN_DISTANCE=<0.05-7>` lets `SCREENSHOT_CAMERA` / `SCREENSHOT_FOCUS` go closer than the game's zoom limit; `SCREENSHOT_TIME_LIMIT=<s>` raises the 60 s run limit (the Suwałki battle needs ~120–180 s); more debug variables are listed in the header of tools/screenshot.gd); under WSL it uses the Windows Godot console build (GPU, D3D12, Forward+ with SSAO – what the human sees) when found, `--linux` forces the WSLg software renderer (Compatibility look)
- `tools/menu_backdrop.sh [--only=map|battle]` – re-render the two stills behind the main menu (`assets/menu/staff_map.png`: staff map without HUD, `assets/menu/battle.png`: the Homar-K salvo frame of the teaser, `tools/teaser.sh --still=<s>`; both 1792×1008 GPU renders, the battle one takes a few minutes); run by `tools/readme_screenshot.sh`, so it follows the graphics work – commit the PNGs (and their `.import`) with the change. `SCREENSHOT_RESOLUTION=WxH` makes `tools/screenshot.sh` render another size; the staff-map token `nohud` hides the whole HUD
- `tools/readme_screenshot.sh` – re-render the README shots `docs/images/gameplay.png` + `staff_map.png` and the main menu backdrops (`tools/menu_backdrop.sh`) (fixed close-up framing, same requirements as `tools/screenshot.sh`)
- `tools/render_unit.sh <unit_id> [--faction=<id>] [--views=side,front,top,three_quarter] [--reference=path] [--out=sheet.png] [--windows|--linux]` – render one unit model alone on a 1 m model-space grid (orthographic side/front/top at the same scale + three-quarter) next to a reference image into `.screenshots/units/<id>_<faction>_sheet.png`; last stdout lines are `Render saved`, `Stats` (AABB in m, triangles, mesh instances, pivots) and `Real` (vs. the unit catalog); used by `/model-unit`; renders with the same Godot build choice as `tools/screenshot.sh`. `tools/render_unit.sh --weapon <means_id> [--views=…] [--reference=path] [--out=sheet.png]` renders a strike weapon model (`WeaponModels`, src/presentation/models/weapons/, TASK-144) on the same sheet (built in metres, scaled to the 1 m grid and set on the ground) into `.screenshots/units/<id>_sheet.png`, with the `Real` line from `docs/design/units/weapons/<id>/unit.json` (tools/render_weapon.gd)
- `tools/teaser.sh [out.avi] [--still=<s>] [--resolution=1920x1080] [--fps=60]` – one-off promo video: the Homar-K's salvo destroys the T-72B3 in the default battle, scripted cinematic camera, fade in, game logo at the end, with the game's sound (forest ambience and birds, rocket launches, explosions); Godot Movie Maker mode (fixed frame rate) writes `.screenshots/teaser/homar_teaser.avi` (MJPEG, ~300 MB at 1080p60, ~2 min render); the camera path in `tools/teaser.gd` is hand-tuned for that pair (its header explains it and the `--spin` camera scout for other pairs); same Godot build choice as `tools/screenshot.sh`
- `tools/simulate.sh N [--seed=S] [--max-turns=T] [--factions=P0,P1] [--scenario=default_battle|objective_battle|command_points_battle|suwalki_battle] [--verbose]` – N headless AI-vs-AI matches: win rates, draws by the rules vs. matches cut by the harness `--max-turns`, average match length (balancing); `--factions` picks the players' factions (default `poland,russia`), `--scenario` the battle (default `default_battle`)
- `tools/import_map.py [<bbox>] --center=<lat,lon> --size=30x24 --hex=250 --name=<id> --out=data/maps/<id>.tres [--offline] [--cache=DIR] [--profile=tactical|operational|layer]` – hex map from real geography (ADR 0018): Copernicus GLO-30 DEM + OpenStreetMap land cover, downloaded once into `~/.cache/eastern-flank/maps` (outside git), then offline and byte-identical; stdlib Python; `--profile=operational` (TASK-092a) makes the 5 km theatre map: 250 m lattice, GLO-90 (`--dem=glo30|glo90`), Overpass in 0.5° tiles (`--tile-deg=`, resumable, retried), sea filled from the coastline (`--sea-seed=lat,lon`), thresholds `--water-share --urban-share --forest-share --marsh-share --hills-relief`; country per hex (TASK-113) from `--countries=ISO:lat,lon,...` seed points (operational defaults PL / LT / BY / RU) and the borders-only tiles `bd1_*.json` (own download, `--offline` fails naming a missing one), also written as drawn border polylines `border_lines` (world units, simplified 0.1 hex); operational maps also get `place_names` / `place_positions` / `place_ranks` (TASK-112: OSM `place=city|town|village` nodes from their own tiles `pl1_*.json`, `--offline` fails naming a missing one; villages need `population` >= 1000, total <= 400); operational maps also get the graphic layers for drawing (TASK-126): `water` (1-bit), `cover` (8-bit class) and `relief` (8-bit hillshade, sun NW 45°, `--relief-z=4` exaggeration, 500 m pixels `--relief-step=2`) images of the 250 m lattice, stored as base64 PNGs in `layer_*_png` (`ImportedMap.layer_image`); the theatre's first download is ~1.9 GB / ~1.7 h, an offline import ~4.5 min and ~0.9 GB RAM (rebuild command in CREDITS); `--profile=layer` (TASK-094b) writes a theatre-wide **tactical layer** for contact battles into the folder `--out` (`layer.tres` + 128 × 128 `chunk_<cx>_<cy>.tres`, `TacticalLayer`): 250 m hexes from the operational cache (op1 tiles + GLO-90) plus its own land-use tiles `lu1_*.json` (farmland / grass for FIELDS, `landuse_query`; same grid, retried, 5 s between downloads; the theatre's first download is ~0.9 GB / ~70 min; `--offline` fails naming a missing one), 50 m cover lattice, DEM at 7 points per hex, hills from 10 m relief; the Suwalki theatre layer takes ~9 min offline and ~1 GB RAM (command in CREDITS); play the committed sample with `tools/run.sh --scenario=suwalki_battle`; attribution in `data/maps/CREDITS`; Python tests (`tools/test_import_map.py`, fixtures re-made with `--make-fixtures`) run in `tools/check.sh`
- `tools/unit_catalog.sh [--port=8765]` – local web tool (Python stdlib, 127.0.0.1 only) for the human to collect real-unit references (facts, dimensions, images, factions) into `docs/design/units/`; it can run `/research-unit` and `/model-unit` as headless Claude Code jobs (ADR 0008); Python tests run in `tools/check.sh`
